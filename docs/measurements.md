- CPU: Intel Core i9-12900 (논리 코어 24개), RAM 63.7 GB, Windows 11 Pro

### 수집 시간을 줄인 과정

처음에는 수집 1회에 약 5.0초(PowerShell CPU 약 1.05초)가 걸렸다. 나눠서 재 보니 다음 두 곳이 대부분이었다.

1. `Get-NetTCPConnection` 이 약 2초 → netstat 과 같은 OS API(`GetExtendedTcpTable`)를 C# 보조 코드로 직접 불러 몇 ms 로 줄였다. 실패하면 `Get-NetTCPConnection` 으로 대신한다. 결과는 같았다(LISTEN 56건 일치).
2. 675 KB 짜리 JSON 한 줄을 PowerShell 출력으로 내보내는 데 약 2초 → UTF-8 바이트를 표준 출력 스트림에 직접 쓰게 바꿨다.

C# 보조 코드는 앱 데이터 폴더(`%APPDATA%\pitwall\pitwall-native-<해시>.dll`)에 한 번만 컴파일해 두고 다시 쓴다.

### 메모리가 목표를 넘는 원인과 조정안

Electron 앱의 기본 프로세스 4개만으로 working set 이 약 375 MB 다. pitwall 의 데이터는 작다(main 프로세스 안의 스냅샷 몇 MB).

| 조정안 | 예상 효과 | 단점 |
| --- | --- | --- |
| 하드웨어 가속 끄기(`app.disableHardwareAcceleration()`) | GPU 프로세스 몫(약 90~115 MB) 대부분 절감 | 대시보드는 GPU 가 필요 없어 사실상 없음. 적용 후 다시 재야 함 |
| 창을 숨길 때 화면(renderer)을 닫고, 열 때 다시 만들기 | 숨긴 동안 약 90 MB 절감 | 다시 열 때 약 1초 걸림 |

두 가지를 모두 적용하면 트레이에 있는 동안 약 200 MB 안팎이 될 것으로 본다. 적용 여부와 효과는 다음 단계에서 다시 재서 정한다.

## 5단계 — Windows 부하 다시 재기 (2026-11-10)

- 대상: `npm run build:unpack` 의 압축 풀린 결과물(`dist/win-unpacked/pitwall.exe --hidden`), 측정용 새 프로필(`--user-data-dir`)에 자동 실행·업데이트 확인·모든 알림을 끄고 Claude·Codex 연동도 켜지 않은 상태. "에이전트가 하는 일 보기"·"토큰 사용량 보기"는 기본값(켬) 그대로. 트레이만 띄운 상태(수집 30초 주기, 요약 창은 열지 않음), 1분 예열 뒤 10분.
- 환경: 1단계와 같은 PC(논리 코어 24개, RAM 63.7 GB). Claude Code 4개, node·java 개발 서버 프로세스 7개(포트 9개), 또 다른 pitwall(개발 실행)이 떠 있었다.

### 무거운 작업 기다리게 하기(G7)의 질문 훅 시간 (2026-11-10)

질문 훅은 "겹치면 에이전트가 기다리게 하기"를 켰을 때만 들어가며, Claude 가 Bash·PowerShell 명령을 실행할 때마다 한 번 돈다.

- 방법: Windows, Git Bash. 실제로 넣는 훅 명령(`<SystemRoot>/System32/curl.exe -s --connect-timeout 0.3 -m 2 --data-binary '@-' '<주소>'; exit 0`)을 `bash.exe -c` 로 5번씩 실행하고, PreToolUse 이벤트 JSON 을 표준입력으로 넘겨 띄운 때부터 끝날 때까지 잰 가운데 값. "켜져 있을 때"는 바로 204 로 답하는 로컬 서버로 쟀다(pitwall 의 판단은 프로세스 안에서 동기로 1 ms 미만이고, 다른 조건이 모두 맞을 때만 작은 package.json 하나를 읽는다). 모든 실행이 종료 코드 0, 출력 없음.

| 경우 | 훅 전체 시간(가운데 값) | 목표 | 판정 |
| --- | --- | --- | --- |
| pitwall 꺼짐(닫힌 포트) | **382 ms** | 600 ms 이하 | 충족 |
| pitwall 켜짐(답함) | **83 ms** | 300 ms 이하 | 충족 |
| 참고: 빈 `bash -c 'exit 0'` | 59 ms | — | — |
| 참고: PowerShell 5.1 로 실행할 때, 꺼짐 / 켜짐 | 472 ms / 151 ms | — | — |

- 빈 셸 실행을 빼면 명령마다 더해지는 시간은 꺼져 있을 때 약 0.32초, 켜져 있을 때 약 24 ms 다. 꺼져 있을 때의 대부분은 연결 제한 0.3초다(Windows 는 닫힌 로컬 포트에 연결하면 실패하기까지 2초쯤 걸려 제한을 둔다).
