예전 이름은 pitwall이에요. 앱 데이터 폴더는 이름이 바뀐 뒤에도 그대로 Windows `%APPDATA%\pitwall`, macOS `~/Library/Application Support/pitwall`을 써요.

## 무엇을 읽고, 무엇을 바꾸나요

모두 내 PC 안에서만 읽고, 읽은 것을 어디로도 보내지 않아요. 아래에서 `<Claude 설정 폴더>`는 `~/.claude`(`CLAUDE_CONFIG_DIR`이 있으면 그 폴더), `<Codex 폴더>`는 `~/.codex`(`CODEX_HOME`이 있으면 그 폴더)예요.

### 늘 읽는 것

- 프로세스 목록과 명령줄·작업 폴더·메모리(Windows는 커밋 포함)·CPU 시간, 시스템 메모리(Windows는 커밋 한도·커널 메모리 포함), 열린 TCP 포트와 연결, git 저장소 정보(브랜치·워크트리 목록·원격 추적 상태).
  - Windows에서는 다른 프로세스의 작업 폴더와 메모리를 알기 위해 작은 C# 보조 코드를 PowerShell로 컴파일해 앱 데이터 폴더에 둬요.
- 에이전트·서버·무거운 작업·남은 프로세스가 도는 워크트리마다 커밋 안 한 변경 수. `git status --porcelain`을 워크트리마다 5분에 한 번 돌려 줄 수만 세요. 잠금 파일을 만들지 않고(`GIT_OPTIONAL_LOCKS=0`), 저장소 설정의 fsmonitor도 띄우지 않아요.
- Claude Code가 실행 중인 프로세스마다 남기는 세션 파일(`<Claude 설정 폴더>/sessions/<pid>.json`)의 세션 id·상태·상태가 바뀐 시각·응답 대기 이유·세션 이름. 지금 도는 Claude 프로세스의 파일만 열고, 같은 폴더의 다른 파일(`.key` 등)은 열지 않아요. 세션 이름은 "에이전트가 하는 일 보기"를 끄면 버려요.
- Codex 세션 기록(`<Codex 폴더>/sessions/`)의 이벤트 종류·시각·작업 폴더. 대화 내용은 읽어 두지 않고(아래 "에이전트가 하는 일 보기"가 켜져 있을 때 끝난 턴의 마지막 말 첫 줄만 예외예요), `auth.json`은 열지 않아요.
- 연동 상태를 보이려고 Claude 설정 파일(`settings.json`)과 Codex 훅 설정 파일(`hooks.json`)을 읽어요(읽기만).

### 설정이 켜져 있을 때만 읽는 것

- **토큰 사용량 보기**(설정 > 에이전트 연동, 기본 켬): Claude 세션 기록(`<Claude 설정 폴더>/projects/<폴더>/<세션 id>.jsonl`)과 Codex 세션 기록에서 토큰 숫자·모델 이름·Codex 사용 한도만 꺼내요. 대화 내용은 남기지 않고, 수집을 늦추지 않게 뒤에서 덧붙은 만큼만 읽어요. 끄면 Claude 세션 기록은 열지 않고, Codex 세션 기록에서는 위의 상태 이벤트만 읽어요.
- **Claude 연동·Codex 연동**: 훅이 보내는 이벤트로 상태를 알아요. **에이전트가 하는 일 보기**(기본 켬)가 켜져 있으면 세션 제목·마지막 요청의 첫 줄(200자)·도구 이름과 요약(셸 명령은 첫 줄 160자, 파일 도구는 파일 이름)·에이전트가 멈추며 남긴 마지막 말의 첫 줄(200자)을 메모리에만 들고 화면에 보여요. 마지막 말은 Claude는 연동이 켜져 있을 때 훅이 알려 주고, Codex는 연동 없이도 세션 기록의 끝난 턴에서 읽어요. 디스크(기록·`history.json`)에는 쓰지 않고 OS 알림에도 넣지 않으며, 끄면 받는 순간 버려요.
- **겹치면 에이전트가 기다리게 하기**(설정 > 무거운 작업, 기본 끔): Claude가 실행하려는 셸 명령을 그 자리에서 보고, 무거운 작업이 이미 돌고 메모리가 경고 기준을 넘었을 때만 그 명령이 부르는 패키지 스크립트(`npm run build` 등)를 그 폴더 `package.json`의 scripts에서 한 단계 찾아봐요. 명령은 판단에만 쓰고 남기지 않아요.

### 인터넷 접속

새 버전 확인 하나뿐이고, 설정 > 일반에서 끌 수 있어요. 사용자 정보는 보내지 않아요. macOS에서는 **설정 → 정보**의 **업데이트**를 눌렀을 때만 GitHub 릴리스에서 새 버전의 설치 파일을 내려받아, 릴리스의 확인 값(sha512)과 맞는지 보고 응용 프로그램 폴더의 Corral을 바꿔 넣어요. 바꿔 넣지 못하면 지금 앱은 그대로 두고 터미널용 설치 한 줄을 알려 줘요.

### 바꾸는 것

- 포트 내리기·프로세스 끄기·의존성 폴더 지우기는 항상 확인 창을 거치고, 누르기 직전에 최신 상태를 다시 확인해요. 자동으로 끄거나 지우는 일은 없어요. 에이전트 자체와, 아래에서 에이전트가 돌고 있는 프로세스는 끄지 않아요.
- Claude 설정 파일(`<Claude 설정 폴더>/settings.json`)은 "Claude 연동 켜기"를 눌렀을 때만 알림 훅을 더하고, "겹치면 에이전트가 기다리게 하기"를 켰을 때만 질문 훅을 하나 더 넣어요. 둘 다 확인 창을 거치고 바꾸기 전에 백업을 남겨요.
- Codex 훅 설정 파일(`<Codex 폴더>/hooks.json`)도 "Codex 연동 켜기"를 눌렀을 때만 바꿔요.
- 에이전트의 동작은 기본으로 바꾸지 않아요. "겹치면 에이전트가 기다리게 하기"를 켰을 때만, 조건이 맞으면 Claude Code에 무거운 명령을 1분쯤 뒤에 다시 실행하라고 답해요(같은 세션·같은 명령 종류는 10분에 두 번까지). Corral이 꺼져 있거나 답하지 못하면 명령은 그대로 실행돼요.
- 앱 데이터 폴더에 설정(`config.json`)·기억한 저장소(`state.json`)·RAM 추이와 기록(`history.json`)을 써요. 기록에는 종류·시각·폴더 이름·브랜치·숫자만 들어가고 프롬프트·명령은 들어가지 않아요. 다시 켜도 추이와 기록은 이어져요.
- 화면 배치(카드 영역 단계·카드 순서·숨긴 카드)와 표 정렬은 이 PC의 앱 저장소(`localStorage`, 앱 데이터 폴더 안)에 남겨요.
- 상세 패널의 바로 가기(경로 복사·폴더 열기·터미널 열기·창으로 가기)는 누를 때만, 지금 목록에 있는 항목의 폴더·창에만 써요.
- 로그인할 때 실행(설정 > 일반, 기본 켬)을 위해 OS 로그인 항목에 등록해요.

## Claude 연동

연동을 켜지 않아도 Claude Code가 남기는 세션 파일로 작업 중·쉬는 중·응답 대기를 알아요. "Claude 연동 켜기"를 누르면 Claude Code 설정 파일에 훅을 더해, 세션 시작·프롬프트·도구 사용(실행 전·후)·권한 요청·알림·응답 끝·오류·세션 끝 이벤트를 Corral의 로컬 포트(127.0.0.1, 무작위 토큰)로 보내요. 그러면 어떤 도구가 권한을 기다리는지, 하는 일, 오류, 조용함까지 알아요. 이 훅은 비동기라 Claude를 기다리게 하지 않아요.

- 바꾸기 전에 원래 파일을 `settings.json.pitwall-backup-<시각>`으로 남겨요.
- 다른 도구가 넣은 훅·주석·다른 설정은 그대로 둬요. 끄면 Corral이 넣은 훅만 정확히 빼요. `statusLine`은 건드리지 않아요.
- Corral이 꺼져 있어도 훅은 조용히 끝나(종료 코드 0) Claude 작업을 방해하지 않아요.
- 이미 실행 중인 Claude 세션은 다시 시작해야 반영될 수 있어요.

**겹치면 에이전트가 기다리게 하기**(설정 > 무거운 작업, 기본 끔)를 켜면 같은 확인 창·백업을 거쳐 질문 훅이 하나 더 들어가요. Claude가 Bash·PowerShell 명령을 실행하기 전에 동기로 Corral에 묻는 훅이에요(연결 제한 0.3초, 훅 제한 3초).

- Corral이 답하지 않거나 어떤 오류가 나도 명령은 그대로 실행돼요. 명령마다 더해지는 시간은 Windows에서 Corral이 켜져 있을 때 수십 ms, 꺼져 있을 때 약 0.3초예요([measurements.md](measurements.md)).
- 끄면 바로 판단을 멈춰요. 설정 파일에서 질문 훅도 뺄지는 따로 물어요.
- 이 훅은 `127.0.0.1:<포트>`에서 답하는 쪽을 그대로 믿어요. Corral이 꺼져 있는 동안 다른 로컬 프로그램이 그 포트를 열면 이벤트를 받고 이 훅에 답할 수도 있어요.

## Codex 연동

"Codex 연동 켜기"는 Claude 연동과 같은 방식(확인 창·백업·다른 훅 보존·끄면 Corral 항목만 뺌)으로 Codex 훅 설정 파일에 훅을 더해, 응답 대기까지 알 수 있게 해요. 켠 뒤 **Codex에서 `/hooks`를 열어 Corral 훅(주소에 `pitwall-hook`이 들어 있는 훅)을 한 번 승인**해야 이벤트가 와요. 연동을 켜지 않아도 Codex 세션 기록으로 작업 중·쉬는 중·오류를 알아요(같은 폴더에서 Codex를 둘 이상 돌리거나 기록을 찾지 못하면 CPU로 짐작).

## 화면

- 위쪽 카드 줄은 **자세히·간단히·접기** 세 가지로 볼 수 있고, 고른 모양은 다시 켜도 기억해요. 문제가 있는 카드(정리 후보, 응답 대기)는 위쪽 선 색으로 강조하고, 할 말이 없는 카드는 작게 줄여요.
- 카드 줄과 탭 사이의 **할 일** 띠에는 지금 사람이 봐야 할 것만 나와요. 응답을 기다리는 에이전트(창으로 가기), 새로 끝난 에이전트(창으로 가기), 메모리 정리 추천(모두 끄기), 정리 후보인 개발 서버(내리기), 무거운 작업 겹침(목록에서 보기) 다섯 가지예요. 줄을 닫으면 그 줄의 상태가 바뀔 때까지 숨겨요.
- **새로 끝남**은 정확한 상태를 아는 에이전트(Claude·Codex 연동, Claude 세션 파일, Codex 세션 기록)가 2분 넘게 일한 뒤 멈췄는데 아직 확인하지 않았다는 표시예요. 에이전트 목록의 상태 칸과 할 일 띠에 뜨고, 마지막 말을 알면 그 첫 줄을 같이 보여요. 그 에이전트에 새 요청을 보내거나, Corral에서 창으로 가기를 누르거나, 띠의 줄을 닫으면 사라져요. Corral을 다시 켜면 표시는 처음부터 다시 세요.
- 탭은 작업 공간·개발 서버·에이전트·남은 프로세스·무거운 작업·디스크 정리가 먼저 보이고, **더 보기**에 다른 앱·기록이 들어 있어요.
- 작업 공간 탭은 작업 공간 줄 아래에 그 안의 에이전트·서버·남은 프로세스를 트리 선으로 묶어 보여 줘요. 서버 이름은 브랜드 이름(예: Vite, OpenJDK)으로 보여요.

## 설정

오른쪽 위 메뉴의 **설정**(또는 트레이 메뉴 > 설정)에서 바꿔요.

- **일반**: 갱신 주기(빠르게 2·10초 / 보통 5·30초 / 절약 15초·2분, 창이 열려 있을 때·닫혀 있을 때), 화면 테마, 로그인할 때 실행, 새 버전 확인
- **기준값**: RAM 경고·위험 기준(기본 80·90%, RAM과 커밋 사용률에 같이 씀), 안 쓰는 포트 기준 시간(기본 20분), 오래 쉬는 세션 기준(기본 180분), 숨긴 서버
- **무거운 작업**: 명령 패턴(예: `vue-tsc`, `vite build`), 겹치면 에이전트가 기다리게 하기
- **알림**: 메모리 부족·응답 대기·작업 끝남·조용한 에이전트·에이전트 꺼짐·무거운 작업 겹침, 알림을 누르면 그 에이전트의 창으로, 응답 대기 다시 알림 간격(기본 10분)
- **디스크 정리**: 지울 폴더 이름(기본 `node_modules`·`.next`·`.nuxt`·`.turbo`·`.vite`·`dist`·`build`·`out`·`target`·`.gradle`, git이 무시하는 것만 지움), 오래 안 쓴 워크트리 기준(기본 14일, 0이면 끔), 더 살펴볼 저장소
- **에이전트 연동**: Claude·Codex 연동 켜기/끄기, 에이전트가 하는 일 보기, 토큰 사용량 보기

## 알려진 한계

- macOS 빌드는 GitHub의 macOS 러너(macOS 15·26, Apple Silicon·Intel)에서 설치와 주요 동작을 자동으로 확인했고, 실제 Mac을 손으로 써 본 것은 아니에요. 알림 배너가 보이는 모습, 권한을 묻는 창, 다시 로그인했을 때의 시작은 러너에서 확인할 수 없었어요. macOS에서는 커밋 값을 몰라요. Windows에서도 보안 정책으로 보조 코드가 막힌 PC는 커밋을 몰라요.
- 회사 보안 프로그램이 서명 없는 실행 파일이나 PowerShell 사용을 막으면 수집 방식이 "제한 모드"로 바뀌고, 일부 정보(작업 폴더 등)가 빠질 수 있어요.
- WSL2·Docker·devcontainer 안에서 도는 서버는 어느 워크트리 것인지 알 수 없어 "판별 불가"로만 보이고 정리 후보가 되지 않아요.
- "끝난 워크트리"는 이 PC의 git 정보(마지막 fetch)로만 판단해요. Corral은 fetch하지 않아요. 디스크 정리는 `git`을 쓰므로, Xcode 명령줄 도구가 없는 Mac에서는 처음 쓸 때 설치 창이 뜰 수 있어요.
- Codex의 응답 대기는 Codex 연동을 켜고 `/hooks`에서 승인해야 알 수 있어요.
- Claude Code의 세션 파일과 세션 기록은 문서화되지 않은 내부 형식이에요. 형식이 바뀌면 연동 없이 아는 상태·토큰 숫자가 안 보일 수 있어요(그때는 CPU로 짐작해요). 출력 합에는 하위 에이전트가 쓴 토큰이 들어 있지 않아요.
- Claude의 사용 한도는 보여 주지 않아요. 알 수 있는 길이 Claude의 상태 줄(`statusLine`) 설정뿐인데 Corral은 그것을 건드리지 않아요.
- 창으로 가기는 macOS의 Terminal·iTerm2에서만 에이전트가 떠 있는 탭까지 골라요(처음 누를 때 macOS가 Corral이 그 앱을 제어해도 되는지 한 번 물어요. 허용하지 않으면 앱만 앞으로 와요). 그 밖의 앱과 tmux 안의 에이전트, Windows는 창까지만 가고 탭은 고르지 못해요. Windows는 다른 앱이 창을 앞으로 가져오는 것을 막을 때가 있어요.
- 조용함은 오래 걸리는 명령(CI 기다리기 등)을 기다릴 때도 떠요. 그래서 "멈춤"이 아니라 "조용함"이라고 불러요.
- 새로 끝남은 Corral 밖에서 그 터미널을 직접 열어 본 것은 알지 못해요(새 요청을 보내면 그때 사라져요). 연동을 켜지 않은 Claude는 마지막 말을 알 수 없어 표시만 떠요. 에이전트가 백그라운드 작업을 남기고 멈춘 경우와, 2분 넘게 일하던 것을 직접 중단한 경우에도 끝난 것으로 표시해요.
- 작업 공간 합계는 작업 공간마다 따로 세요. 두 작업 공간에 걸친 프로세스는 양쪽 합계에 모두 들어가므로 묶음끼리 더하지 마세요.
- macOS에서 Dock·Finder로 켜면 셸 설정 파일에서만 정한 `CLAUDE_CONFIG_DIR`을 모를 수 있어요. 설정 > 에이전트 연동에 Corral이 쓰는 설정 파일 경로가 나오니 확인해 주세요.
