# pitwall 4단계 설계 — 작업 묶음과 편의 기능

작성: 2026-11-09. 앞선 설계: `2026-11-06-pitwall-design.md`(목표 8개, 모두 구현됨). 이 문서는 그 위에 더하는 기능과,
화면을 NeoHtop 디자인으로 바꾸면서 달라진 점을 정리한다.

## 1. 왜

- 사용자는 한 PC 에서 **작업 공간 여러 개**를 동시에 돌린다. 예: 바깥 저장소(여러 저장소를 묶는 작업 공간 저장소) 하나 안에 `repos/` 아래
  프런트(vite)·API(java)·게이트웨이 저장소가 있고, 바깥 저장소에서 Claude 에이전트가 일한다. 같은 구성이 Orca 작업
  공간마다 하나씩 더 있다. 지금 pitwall 은 포트 한 줄씩 보여 줘서 "어느 작업 공간의 서버들인지"가 안 보이고, 정리도
  하나씩 해야 한다.
- 한 서버가 포트를 여러 개 연다(java 부모·자식이 6176·8081·9091). 지금은 포트마다 한 줄이라 메모리를 겹쳐 세고,
  정리 추천도 같은 서버를 두 번 끄려 한다(정확성 문제).
- 데이터 정확성 리포트(2026-11-09)에서 확신도가 낮았던 곳: 에이전트 상태(CPU 추정 65%), "정말 안 쓰는 서버"(80%),
  앱을 다시 켜면 판단 시간이 0 부터 시작함.

## 2. 목표 — 이번 단계에 넣는 것

### F1. 서버 단위로 보기 + 작업 공간 묶음 (사용자 요청)
- **서버 = 포트를 연 프로세스 트리의 맨 위 프로세스.** 같은 트리 안에서 포트를 연 프로세스가 다른 포트 프로세스의
  자손이면 그 조상 서버의 일부다. 한 서버가 연 포트는 한 줄에 모두 보인다(`:6176 · :8081 · :9091`).
  메모리·하위 프로세스는 한 번만 센다. 끄기는 그 서버 트리 전체.
- **데이터 단위를 포트에서 서버로 바꾼다.** 스냅샷·정리 판단·정리 추천·한꺼번에 끄기·알림·트레이·표·상세 패널이
  모두 서버를 단위로 쓴다(지금 포트 단위라 겹쳐 세는 문제를 근본적으로 없앤다). 선택 키는 `server:<pid>:<시작 시각>`.
- **연결 수**는 그 서버의 모든 포트에 붙은 연결의 합. 정리 판단(정리 후보·확인해볼 것)도 서버 단위.
- **작업 공간 = 서버 워크트리의 가장 가까운 바깥 git 저장소.** 워크트리 루트의 부모 폴더들을 위로 올라가며 `.git`
  (폴더 또는 파일)이 있는 첫 폴더. 없으면 그 워크트리 자체가 작업 공간(혼자인 묶음). 남은 프로세스·무거운 작업도
  같은 규칙으로 작업 공간을 갖는다.
  - **같은 저장소면 묶지 않는다(Claude 판단, 빌더 점검 반영):** 바깥 `.git` 이 그 워크트리와 같은 저장소(같은 git 공용
    폴더)면 바깥으로 보지 않는다. `<저장소>/.claude/worktrees/<이름>` 처럼 저장소 안에 만든 병렬 워크트리들이 한 묶음이
    되어, 묶음 정리(F2) 한 번이 다른 세션의 서버까지 끄는 일을 막는다. 작업 공간 저장소처럼 바깥이 **다른** 저장소일 때만 묶는다.
- **작업 공간의 에이전트** = 그 작업 공간 루트 또는 묶음 안 워크트리를 덮는(같거나 상위 폴더) 에이전트.
- **화면(NeoHtop ToolBar 의 "List / Tree" 전환을 따른다):** 개발 서버 탭 도구줄에 "목록 / 묶음" 전환.
  - 묶음 보기: 작업 공간 머리 줄(펼치기 화살표, 이름, 에이전트 로고·상태, 서버 수, 메모리 합, 상태 요약) 아래에
    서버 줄이 들여쓰기로. NeoHtop 트리 보기의 "family" 줄 모양.
  - 고른 보기는 기억한다(정렬처럼). 처음에는 묶음 보기.
- **개발 서버 카드:** 큰 숫자는 서버 수, 아래 줄은 "포트 n개 · 작업 공간 m곳".

### F2. 작업 공간 한 번에 정리 (사용자 요청)
- 묶음 머리 줄의 "정리" 버튼 → 그 작업 공간의 **서버 + 남은 프로세스**를 확인 창 한 번으로 끈다.
- **무거운 작업은 끄지 않는다**(첫 설계의 사용자 결정 "무거운 작업은 경고만"). 에이전트도 끄지 않는다.
- 확인 창에 항목·메모리 합을 보이고, 그 작업 공간에서 에이전트가 실행 중이면 "Claude 가 이 작업 공간에서 실행 중
  (쉬는 중)이에요. 서버를 꺼도 에이전트는 그대로예요"를 덧붙인다.
- 지금 "모두 끄기"와 같은 안전 규칙: 확인 창 전후로 다시 샘플링해 바뀐 항목은 건너뛰고, 에이전트를 자손으로 둔
  프로세스는 끄지 않는다.

### F3. 에이전트 상태 경과 시간
- 표·상세 패널에 "작업 중 · 12분", "권한 대기 · 3분"처럼 지금 상태가 이어진 시간.
- 훅(정확한 상태)은 그 상태가 된 이벤트 시각부터, CPU 추정은 pitwall 이 그 상태를 처음 본 시각부터 잰다.

### F4. 에이전트 작업 끝남 알림
- 정확한 상태를 아는 에이전트(Claude 훅, F7 의 Codex)가 "작업 중 → 쉬는 중"이 되면 OS 알림
  ("shop-web 의 Claude 가 작업을 끝냈어요"). CPU 추정만으로는 알리지 않는다(잘못 알리기 쉬움).
- 설정 > 알림에 항목 추가, 기본값 켬. pitwall 창이 앞에 있으면 알리지 않고, 동시에 여럿이면 하나로 묶는다.
- **오래 걸린 작업만 알린다(Claude 판단, 빌더 점검 반영):** Claude 는 답할 때마다 "작업 중 → 쉬는 중"이 되므로,
  터미널에서 주고받는 동안 매번 알리면 시끄럽다. "작업 중"이 **2분 이상** 이어진 뒤 끝났을 때만 알린다(F3 의 상태 시작 시각 사용).

### F5. 서버 CPU
- 서버(트리 전체) CPU 사용률을 에이전트와 같은 방식으로 잰다(지난 샘플 대비 누적 CPU 시간 변화).
  표 칸·상세 패널에 보인다. 표시 기준은 에이전트와 같다(Windows 전체 CPU 대비, macOS 코어 1개 = 100%).

### F6. 메모리가 계속 느는 서버 표시
- 메인 프로세스가 서버별 메모리를 1분에 한 번, 최근 60분까지 기억한다.
- 최근 30분 이상에서 **처음보다 50% 이상 그리고 1 GB 이상** 늘었고, 1분 간격 변화의 80% 이상이 줄지 않았으면
  "메모리 증가" 표시(표 상태 옆 배지, 상세 패널에 "30분 동안 2.1 GB → 3.6 GB"). OS 알림은 보내지 않는다(시끄러움).

### F7. Codex 상태 정확도
- 원칙: 사용자 Codex 설정은 사용자가 켤 때만 바꾸고(Claude 연동과 같은 방식), `~/.codex/auth.json` 은 열지 않으며,
  대화 내용은 읽지도 저장하지도 않는다(이벤트 종류·시각만).
- 조사 결과(2026-11-09, openai/codex rust-v0.167.0·공식 문서):
  - **Codex hooks**(`~/.codex/hooks.json` 또는 `config.toml [hooks]`): UserPromptSubmit·PreToolUse·PostToolUse → 작업 중,
    PermissionRequest → 권한 대기, Stop·Interrupt → 쉬는 중. Claude 연동처럼 이벤트를 pitwall 로컬 포트로 보낸다.
    Codex 0.129 이상, Windows 지원(0.120+). **사용자가 Codex 의 `/hooks` 에서 한 번 승인해야** 실행된다.
    에러로 끝난 턴에는 Stop 이 오지 않는다(세션 기록으로 보완).
  - **세션 기록(rollout) 읽기**(`$CODEX_HOME/sessions/YYYY/MM/DD/rollout-*.jsonl`, 설정 변경 없음, Codex 0.100+):
    마지막 `task_started` 뒤에 `task_complete`·`turn_aborted` 가 없으면 작업 중, 있으면 쉬는 중, `task_complete.error`
    면 오류. 권한 대기는 기록되지 않아 알 수 없다. 줄의 `type` 만 읽고 대화 내용은 버린다. 프로세스와 기록 파일은
    세션 기록의 작업 폴더·시작 시각으로 잇는다(Windows 는 pid 가 기록에 없음).
  - `notify` 설정은 정보가 적고 Windows 버그가 있어 쓰지 않는다.
- **정함(2026-11-09 사용자 결정 — 둘 다):** 기본은 세션 기록 읽기(작업 중·쉬는 중·오류), "Codex 연동 켜기"를 누르면
  hooks 로 권한 대기까지. 연동을 켜면 화면에 "Codex 에서 /hooks 승인을 한 번 해 주세요" 안내를 띄운다.
  둘 다 안 되면(구버전 등) 지금처럼 CPU 추정.

### F8. 앱을 다시 켜도 기록 이어 가기
- 앱 데이터 폴더의 `history.json` 에 저장: RAM 추이(최근 2시간, 30초 간격), 서버별 메모리 기록(F6),
  정리 판단 기억(서버별 상태·시작 시각), 에이전트 상태 시작 시각(F3). 5분마다와 종료할 때 쓴다.
- 다시 켤 때 **꺼져 있던 시간이 10분 이하**면 판단 기억을 이어 쓴다(업데이트 설치·재시작). 더 길면 판단 기억은
  버린다(꺼진 동안 쓰였는지 모르므로 — 불확실하면 후보에서 빼는 쪽). RAM 추이는 끊긴 구간을 비운 채 보인다.

### F9. "정말 안 쓰는 서버" 판단 보강
- 지금은 "연결이 있느냐"만 본다. 여기에 **최근 사용 흔적**을 더한다:
  - 서버 포트에 TIME_WAIT 연결이 있다(최근 닫힌 요청. Windows 는 소유 pid 가 0 이라 포트로 맞춘다), 또는
  - 지난 샘플에 없던 새 연결(상대 포트가 다른 ESTABLISHED)이 생겼다.
- **흔적은 "연결 0" 타이머에만 쓴다(Claude 판단, 빌더 점검 반영).** 연결이 0 으로 보여도 그 사이 요청이 오가고 닫힌
  흔적이 있으면 "연결 없음" 시작 시각을 지금으로 되돌린다 → 샘플 사이에만 짧게 요청을 받는 서버(다른 서버·CLI 가 가끔
  부르는 API)가 정리 후보로 잘못 오르지 않는다.
- **"확인해볼 것"(연결이 이어짐) 타이머에는 쓰지 않는다.** 대시보드처럼 몇 초마다 요청하는 탭은 열어 두기만 해도 새
  연결을 만들므로, 여기에 쓰면 잊고 둔 탭이 영영 "확인해볼 것"이 되지 않는다. 지금처럼 연결이 이어진 시간만 본다.
- 같은 작업 공간 서버끼리 오가는 연결(프런트 프록시 → API)도 흔적으로 친다. 연결 0 이 아니라는 것은 그 묶음이 쓰이고
  있다는 뜻이라 후보에서 빼는 쪽이 맞다.
- macOS 의 `lsof` 는 TIME_WAIT 를 주인 프로세스와 잇지 못해 새 연결만 본다.

### F10. 트레이 요약 창 (사용자 결정: 만든다)
- NeoHtop 의 메뉴바 요약 창(MenuBarOverview) 모양: RAM 막대·에이전트 상태·작업 공간별 서버 수·정리 추천 버튼,
  아래에 "앱 열기"·"설정"·"종료".
- 트레이 **왼쪽 클릭 = 요약 창, 오른쪽 클릭 = 지금 OS 메뉴**(2026-11-09 사용자 결정. 첫 설계의 "OS 기본 메뉴"에 더한다).
  macOS 는 메뉴바 아이콘 아래, Windows 는 작업 표시줄 트레이 위에 붙여 띄우고, 다른 곳을 누르면 닫힌다.

### F11. 숨기기·별칭
- **숨기기:** 서버(포트 번호 또는 프로세스 이름)를 목록에서 숨긴다. 숨긴 것은 개수·정리 판단·추천·알림·트레이에서
  빠진다. 표 바닥에 "숨김 n개" 를 누르면 다시 보이고 숨김을 풀 수 있다. 설정 > 기준값 아래 "숨긴 서버" 목록.
- **별칭:** 작업 공간 머리 줄의 이름을 바꿀 수 있다(설정에 `작업 공간 경로 → 이름`으로 저장).

### F12. 디스크 정리 범위
- **빌드 결과 폴더도 대상:** 기본 목록에 `.next`, `.nuxt`, `.turbo`, `.vite`, `dist`, `build`, `out`, `target`,
  `.gradle` 을 더한다(설정에서 고칠 수 있음, 지금처럼 워크트리 바로 아래 이름만).
- **새 안전 규칙(모든 폴더에 적용, node_modules 포함):** 그 폴더가 git 이 **무시하는(ignored) 폴더일 때만** 지운다
  (`git check-ignore`). 저장소에 올라간 `build/` 같은 소스 폴더는 이름이 같아도 지우지 않는다.
- **워크트리 자체 지우기 — 하지 않는다(2026-11-09 사용자 결정).** 아래는 검토 기록: 끝난 워크트리 상세 패널에 "워크트리 지우기" 버튼.
  `git worktree remove`(강제 없이 — 고친 파일·새 파일이 있으면 git 이 거절)로만 지우고, 지우기 전후 확인 규칙은
  의존성 폴더 지우기와 같다. 첫 설계의 "워크트리 자체는 지우지 않는다"(Claude 판단)를 바꾸는 것이다.
  - **주의(빌더 점검):** `git worktree remove` 는 git 이 **무시하는** 파일·폴더(`.env`, 로컬 설정, 작업 공간 저장소의
    `repos/` 처럼 안에 다른 저장소가 든 폴더)를 묻지 않고 같이 지운다. 넣는다면: 지울 수 있는 폴더 목록 밖에
    무시된 파일이 하나라도 있거나 안에 다른 git 저장소가 있으면 거절한다(`git status --ignored` 로 확인).

### R. 출시 전에 할 것(기능 아님)
- R1 새 화면 기준 화면 동작 테스트 다시 쓰기(끄기·지우기 결과 알림, 알림에서 항목으로 이동, 저장 안 한 설정 유지,
  탭·정렬·검색, 묶음 보기).
- R2 부하 다시 재기(창 닫힘 평균 CPU 1% 미만, 앱 RAM 300MB 미만). 넘으면 원인을 찾아 줄인다.
- R3 설치 파일 다시 만들기. R4 설계 문서·README 를 NeoHtop 화면 기준으로 고치기(첫 설계 §7 디자인 기반 줄 포함).

## 3. 비목표
- 무거운 작업을 끄거나 기다리게 하는 것(첫 설계 사용자 결정 유지 — F2 에서도 끄지 않는다).

- 확인 없이 끄거나 지우는 것. 묶음 정리·워크트리 지우기도 확인 창을 거친다.
- 에이전트가 일하는 작업 공간의 서버를 **정리 후보로 자동 추천**하는 것(F2 의 직접 정리는 사용자가 누른 것이라
  경고와 함께 허용).
- 같은 프로세스를 두 번 세거나 두 번 끄려는 것(F1 의 이유).
- git 이 추적하는 파일을 지우는 것(F12).
- 회사 경로·이름이 레포에 들어가는 것(테스트 표본은 `C:\work\...` 같은 일반 경로).
- 감시하는 앱이 무거워지는 것(R2).

## 5. 제약
- Windows + macOS, 한국어 화면(Pretendard, 자연스러운 한국어 문구).
- 화면 모양은 NeoHtop(MIT)의 실제 부품을 따른다: 묶음 보기는 NeoHtop 트리 보기, 요약 창은 NeoHtop 메뉴바 요약 창.
- 실제 `~/.claude/settings.json` 은 사용자가 앱에서 켤 때만, 개발·테스트는 임시 `CLAUDE_CONFIG_DIR`.
- 데이터 판단은 순수 함수로 나눠 테스트한다(지금 `rows.ts`·`judge.ts` 처럼). 버그 수정은 실패하는 테스트부터.
