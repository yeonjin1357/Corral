# pitwall 5단계 설계 — 메모리 압박·에이전트 주의·작업 공간 보기

작성: 2026-11-10. 앞선 설계: `2026-11-06-pitwall-design.md`(목표 8개), `2026-11-09-pitwall-4-features-design.md`(4단계).
이 문서는 실제 PC 에서 수집기를 돌려 본 결과에서 나온 개선을 정리한다. 사용자는 2026-11-10 에 "말한 내용을 모두, 예전 결정과
부딪히는 것도 제안대로" 하기로 했다. 세부 값은 대부분 Claude 판단이다(§7 에 모았다).

## 1. 왜

사용자가 하루 종일 묻는 것은 네 가지다. ① 지금 내가 봐 줘야 하는 에이전트가 있나 ② PC 가 왜 느린가, 무거운 작업을 하나 더
돌려도 되나 ③ 이 포트·프로세스는 어느 작업 것이고 꺼도 되나 ④ 끝난 작업의 뒷정리. 지금 구현은 ③이 가장 강하고 ①②가 약하다.

작성자 PC 실측(2026-11-10, RAM 64 GB, 에이전트 6개·개발 서버 7개):

- **메모리가 부족할수록 숫자가 작게 보인다.** Windows 는 메모리가 모자라면 프로세스 메모리를 페이지 파일로 밀어낸다. pitwall 은
  RAM 에 올라온 양(전용 작업 세트)만 센다. vite 서버 하나가 화면에는 1.2 GB, 커밋(페이지 파일로 밀려난 것 포함)은 4.2 GB.
  java 서버 한 쌍은 1.7 GB 대 6.8 GB. 시스템 전체는 RAM 89% 로 보이지만 커밋이 한도의 82%(104.8 / 127.7 GB)이고 페이지 파일을
  30 GB 쓰고 있었다. "끄면 약 X GB 확보"도 같은 값이라 작게 나온다.
- **사용 중 메모리의 31% 가 "시스템·공유" 한 덩어리**로만 보인다(개발 서버·에이전트 몫은 18%).
- **정리 판단이 사실상 꺼져 있다.** RAM 89% 인데 정리 후보·남은 프로세스·정리 추천이 모두 0. 서버 7개 중 6개가 "같은 작업 공간에
  에이전트가 있다"로 판단에서 빠졌는데, 그 에이전트는 13일·5일째 떠 있는 세션이었다. 규칙이 에이전트의 최근 활동을 보지 않는다.
- **"나를 기다리는 에이전트"가 얕다.** 트레이 아이콘은 RAM 색만, 권한 대기 알림은 한 번뿐, 누르면 pitwall 창이 열린다(답은
  터미널에서 해야 한다). 무엇을 기다리는지·마지막 활동이 언제인지 화면에 없다. 상태는 워크트리 단위로 합쳐 같은 폴더의 두 세션이
  같은 상태로 보인다. 기록이 없어 자리를 비운 사이 일을 알 수 없다.
- **Claude Code 는 실행 중인 프로세스마다 세션 파일을 남긴다**(`<Claude 설정 폴더>/sessions/<pid>.json`: pid·세션 id·상태(idle·busy)·상태가 바뀐
  시각·이름). 훅 이벤트에는 pid 가 없어 지금은 세션과 프로세스를 추측으로 잇는데(같은 워크트리·가까운 시작 시각), 이 파일로 정확히 이을 수
  있고 훅 없이도 작업 중·쉬는 중을 안다. 13일·5일째 떠 있던 세션은 실제로는 17~19시간 전까지 쓰였다.
- **보는 단위가 종류별 탭**이라 한 작업(에이전트 + 서버 + 빌드)의 전체를 보려면 탭 넷을 돌아야 한다.
- 자잘한 것: 기억한 저장소 35개 중 27개가 이미 지워진 임시 저장소, "다른 앱"의 node.exe 2 GB 는 에디터의 보조 프로세스인데 이름이
  없음, 워크트리 없는 포트(로컬 DB 등)는 찾을 수 없음, 디스크 정리는 머지·원격 삭제된 워크트리만 봄, RAM 이 늘 80% 를 넘는 PC 에서는
  경고 색이 신호 구실을 못 함.

## 2. 목표 — 이번 단계에 넣는 것

### G1. 메모리: 커밋과 남은 메모리
- **프로세스별 커밋 크기**를 같이 모은다. Windows 는 지금 읽는 `PROCESS_MEMORY_COUNTERS_EX2`(전용 작업 세트 = 80번째 바이트)의
  `PrivateUsage`(72번째 바이트). 수집 비용은 늘지 않는다. macOS 는 모른다(null) — 화면은 모르는 값을 숨긴다.
- **시스템 값**: 커밋 합계·커밋 한도, 커널 메모리(paged + nonpaged pool). Windows `GetPerformanceInfo` 한 번(같은 보조 코드).
  보조 코드가 막힌 PC(수집 방식 basic·safe)와 macOS 는 null.
- **행과 묶음에 커밋 합**: 서버·에이전트·무거운 작업·남은 프로세스·다른 앱·프로세스 묶음·메모리 묶음 모두 `commitBytes`
  (구성 프로세스 가운데 하나도 모르면 null).
- **메모리 요약**: `availableBytes`(남은 메모리), `commit { usedBytes, limitBytes, percent, level } | null`,
  `kernelBytes | null`. `level` 은 **RAM 단계와 커밋 단계 중 높은 쪽**이다(커밋 단계는 같은 경고·위험 기준 %를 커밋 사용률에 적용).
  어느 쪽 때문인지 알 수 있게 `ramLevel` 을 같이 둔다.
- **화면**: 메모리 카드에 "남은 메모리 6.5 GB"와 "커밋 104.8 / 127.7 GB (82%)". 메모리 상세에 커밋·한도·남은 메모리, "시스템·공유"
  안의 커널 몫, 설명 문구(커밋이 무엇인지 한 줄). 서버·에이전트·무거운 작업·남은 프로세스 표와 상세 패널에 "커밋" 칸(값을 하나도
  모르면 칸을 숨긴다). 묶음 머리·트레이 요약 창도 같은 값.
- **확보 예상**: 정리 추천·확인 창·알림은 "RAM 약 1.2 GB · 커밋 약 4.2 GB"처럼 둘 다 보이고(커밋을 모르면 RAM 만),
  추천 순서는 커밋(모르면 RAM) 큰 순.
- **메모리 증가(F6)** 는 커밋이 있으면 커밋으로 잰다(작업 세트는 압박 때 줄어 새는 서버를 놓친다). 기록 형식이 바뀌므로
  `history.json` 은 version 2 로 올리고 예전 파일은 버린다(작업 세트 기록 뒤에 커밋 기록이 이어지면 가짜 증가가 된다).
- **RAM 부족 알림 재무장**: 지금은 정상으로 내려와야 다시 알린다. 늘 80% 를 넘는 PC 에서는 한 번 알리고 끝이다.
  위험 아래로 5분 이상 내려가 있었으면 다시 알릴 수 있게 한다(30분 간격 제한은 그대로). 알림 제목은 원인을 따른다
  (RAM 이면 지금 문구, 커밋이면 "메모리 한도에 가까워요 (커밋 n%)").

### G2. 에이전트 활동을 보는 정리 판단
- **마지막 활동 시각** `AgentRow.lastActiveAt`: 훅은 그 프로세스 세션의 마지막 "활동" 이벤트 시각(SessionStart·UserPromptSubmit·
  PreToolUse·PostToolUse·PermissionRequest·Stop·StopFailure·Interrupt — 60초 뒤에 오는 idle 알림은 활동이 아니다).
  Claude 세션 파일(G3a)은 상태가 바뀐 시각(busy 면 지금). Codex 세션 기록은 마지막 이벤트 시각. CPU 추정은 pitwall 이 마지막으로 "작업 중"으로 본 시각이고, 본 적이 없으면 pitwall 이 그
  에이전트를 처음 본 시각(그 전은 모르므로 보수적으로).
- **오래 쉬는 세션** `AgentRow.parked`: 상태가 쉬는 중·오류·확인 중이고 마지막 활동이 기준 시간(설정 `agentParkedMinutes`,
  기본 180분) 이상 전. 작업 중·권한 대기는 아무리 오래여도 아니다.
- **판단 규칙 변경**: 오래 쉬는 에이전트는 서버를 "보호"하지 않는다. 그 워크트리·작업 공간을 덮는 에이전트가 모두 오래 쉬는
  세션이면 서버를 판단하되 **"확인해볼 것"까지만** 올린다(정리 후보·정리 추천에는 넣지 않는다). 행에 `parkedAgent: true`,
  상태 문구는 "확인해볼 것 · 에이전트가 3시간째 쉼".
- **연결 타이머는 에이전트가 있어도 계속 잰다**(지금은 에이전트가 있으면 지운다). 판단만 막는다. 그래서 에이전트가 있는 서버도
  상세 패널에서 "연결 없음 · 2시간"을 본다. 타이머 시작 시각은 "보호가 끝난 기준 시각"보다 앞설 수 없다: 에이전트가 꺼졌으면 그때,
  오래 쉬는 세션이 됐으면 그 에이전트의 마지막 활동 시각(지금처럼 "떠나면 처음부터 센다"를 지킨다).
- 남은 프로세스의 "에이전트 워크트리" 표시는 바꾸지 않는다(오래 쉬는 에이전트여도 그대로 — 이번에는 서버만).
- 에이전트 표·카드에 "오래 쉼" 표시(끄지는 않는다 — 에이전트를 끄지 않는 원칙은 그대로).

### G3. 나를 기다리는 에이전트
- **G3a 상태를 프로세스 단위로**: 에이전트 행의 상태는 그 프로세스와 짝지은 세션(`processKey`)에서 얻고, 아직 짝이 없는 세션만
  지금처럼 워크트리 단위로 붙인다. 같은 폴더의 두 세션이 서로 다른 상태로 보여야 한다.
  - **Claude 실행 중 세션 파일을 읽는다**(`sessions/<pid>.json` 의 pid·세션 id·상태·상태가 바뀐 시각·이름만. 같은 폴더의 `.key`
    파일은 열지 않는다). 파일의 세션 id 로 훅 세션과 프로세스를 정확히 잇는다. 파일이 없으면(예전 Claude Code) 지금의 추측을 쓴다.
  - **훅이 없을 때의 상태 출처로도 쓴다**: busy → 작업 중, idle → 쉬는 중, 그 시각이 상태 시작 시각. 훅과 세션 파일이 둘 다 있으면 더 늦은 근거를
    따르고(훅 전달이 끊긴 세션이 옛 상태로 굳지 않게), 둘 다 없으면 CPU 추정. 권한 대기는 여전히 훅이 있어야 안다. 내부 형식이라 모양이 다르면 버리고 CPU 추정으로 돌아간다.
  - 살아 있는 프로세스와 짝지은 훅 세션은 6시간 소식이 없어도 버리지 않는다(지금은 6시간 뒤 만료 — 오래 쉬는 세션의 정보를 잃는다).
  - Codex 는 지금 규칙 그대로(같은 폴더에 둘이면 세션 기록을 고르지 않는다).
- **G3b 하는 일 보기(예전 결정 변경, §6)**: 훅 이벤트에서 다음을 **메모리에만** 들고 화면·알림에 보인다.
  세션 제목(`session_title`, 없으면 세션 파일의 이름), 마지막 프롬프트의 첫 줄(200자), 지금 실행 중인 도구(이름·요약·시작 시각 — Claude 훅에
  PreToolUse 를 더한다), 권한을 기다리는 도구(이름·요약). 요약은 Bash·PowerShell 은 명령 첫 줄(160자), 파일 도구는 파일 이름, 그 밖은 없음.
  설정 `showAgentActivity`(기본 켬)를 끄면 받는 순간 버린다. 디스크(history.json·기록)에는 쓰지 않는다.
- **G3c 조용한 에이전트**: 훅으로 "작업 중"인데 이벤트가 없고 트리 CPU 가 작업 기준(2%) 아래인 상태가 15분 이어지면
  `AgentRow.quietSince` 를 채우고 "15분째 조용함"으로 보인다(멈췄다고 단정하지 않는다 — 긴 대기 명령일 수 있다).
- **G3d 트레이 아이콘 표시**: 권한 대기 또는 조용한 에이전트가 있으면 아이콘에 주황 점. 풍선말에 "권한 대기 n".
- **G3e 알림**: 권한 대기 알림 본문에 기다리는 도구 이름("Bash"). 명령·프롬프트는 OS 알림에 넣지 않는다(알림 센터가 디스크에 남긴다 —
  그것은 pitwall 창에서만 본다). 계속 기다리면 다시 알림(설정
  `waitingReminderMinutes`, 기본 10분, 0 이면 끔). 새 알림 둘: 조용한 에이전트(`notify.agentQuiet`, 기본 켬),
  작업 중·권한 대기이던 에이전트가 꺼짐(`notify.agentGone`, 기본 켬). 모두 pitwall 창이 앞에 있으면 보내지 않는다.
- **G3f 바로 가기**: 상세 패널(서버·에이전트·남은 프로세스·무거운 작업·디스크)에 경로 복사·폴더 열기·터미널 열기, 작업 공간 머리에 폴더 열기.
  에이전트에는 **"창으로 가기"**: 그 에이전트 프로세스의 조상 가운데 보이는 창을 가진 첫 프로세스(터미널·에디터 등)를 앞으로 가져온다
  (Windows 는 보조 코드, macOS 는 `.app` 번들 조상을 `open` 으로). 탭까지 고르지는 못한다. 에이전트 알림을 누르면 먼저 창으로
  가기를 해 보고(설정 `notifyClickFocus`, 기본 켬) 안 되면 지금처럼 pitwall 을 연다. 메인은 화면이 준 경로를 그대로 믿지 않고
  지금 스냅샷에 있는 경로만 연다.
- **G3g 기록**: 메인이 일어난 일을 300개·24시간까지 기억하고(`history.json`) "기록" 탭에 보인다. 종류: 에이전트 시작·꺼짐
  (작업 중이었는지), 작업 끝남(걸린 시간), 권한 대기, 오류, 조용함, 서버 시작·꺼짐, 무거운 작업 시작·끝(최대 메모리·걸린 시간),
  메모리 단계 변화, 정리(끈 개수·확보량), 디스크 지움, 에이전트를 기다리게 함(G7). 내용(프롬프트·명령)은 담지 않는다 — 종류·시각·
  폴더 이름·브랜치·숫자만. 창을 10분 넘게 안 보다가 다시 보면 "자리 비운 사이" 카드로 그 사이 일을 한 줄로 요약한다
  ("42분 동안: 작업 끝남 2 · 권한 대기 1 · RAM 최고 96%").

### G4. 작업 공간 보기
- 새 첫 탭 "작업 공간"(처음 켰을 때 기본 탭). 작업 공간 한 줄(머리): 이름, 에이전트 로고·상태, 서버 수·포트, 무거운 작업·남은
  프로세스 수, **그 작업 공간 전체의 메모리·커밋 합**(프로세스마다 한 번 — 에이전트 아래에서 도는 무거운 작업을 겹쳐 세지 않는다),
  커밋 안 한 변경 수, 마지막 활동. 머리 동작은 이름 바꾸기·작업 공간 정리·폴더 열기.
- 펼치면 그 작업 공간의 에이전트·서버·무거운 작업·남은 프로세스가 한 표에(종류 칸), 각자 탭과 같은 동작. 누르면 같은 상세 패널.
- 합계는 메인이 pid 집합으로 계산해 스냅샷에 `workspaces` 로 담는다. 작업 공간을 모르는 것은 "작업 폴더 모름" 한 줄.
- **커밋 안 한 변경**: 작업 공간에 든 워크트리마다 `git status --porcelain` 줄 수(5분에 한 번, 시간 제한, 잠금 파일을 만들지
  않음). 모르면 비운다.
- 개발 서버 탭의 묶음 보기는 그대로 둔다.

### G5. 작은 것
- **G5a** 기억한 저장소: 없어진 저장소(ENOENT)는 불러올 때와 찾을 때 목록에서 뺀다. OS 임시 폴더 아래 저장소는 기억하지 않는다.
- **G5b** 다른 앱: node·java·python 같은 런타임 프로세스는 띄운 앱(가장 가까운 조상 가운데 런타임·셸이 아닌 것)별로 나눠
  "node (Cursor)"처럼 보인다. 띄운 앱을 모르면 지금처럼.
- **G5c** 다른 포트: 개발 서버로 올리지 않은 LISTEN 포트(1024 이상)를 `otherPorts` 로 담아, 개발 서버 탭 바닥의 "다른 포트 n개"로
  보고(포트·프로세스·PID·메모리, 끄기 없음), 검색한 포트가 개발 서버에 없으면 "다른 포트에서 찾기"를 권한다.
- **G5d** 디스크: **오래 안 쓴 워크트리**도 보인다. 연결된 워크트리(detached 포함)가 끝난 근거는 없지만 마지막 커밋과 git 색인
  파일이 모두 기준(설정 `staleWorktreeDays`, 기본 14일, 0 이면 끔)보다 오래됐고 실행 중인 것이 없으면 근거 "오래 안 씀(n일)",
  상태 "확인해볼 것"으로 올린다. 지우는 것은 지금과 같다(git 이 무시하는 의존성·빌드 폴더만, 확인 창, 지우기 직전 다시 확인).

### G6. 토큰·한도 (예전 범위 밖 → 넣는다, §6)
- **Claude**: 훅이 알려 주는 세션 기록 파일(`transcript_path`)을 Codex 기록처럼 덧붙은 만큼만 읽어, 줄의 `message.usage` 숫자와
  `message.model` 만 꺼낸다(같은 `message.id` 는 마지막 값 하나). 컨텍스트 크기 = 마지막 요청의 입력 + 캐시 토큰, 출력 합.
  이 형식은 Claude Code 내부 형식이라 문서가 없다 — 값이 없으면 비운다(지어내지 않음). 큰 파일(64 MB 초과)은 끝 16 MB 만 읽고
  합계는 비운다. 연동이 꺼져 있으면 읽지 않는다.
- **Codex**: 세션 기록의 `token_count` 이벤트에서 합계·컨텍스트 크기·컨텍스트 한도, 그리고 **사용 한도**(5시간·주간 사용률과
  초기화 시각, 요금제 이름)를 읽는다.
- **화면**: 에이전트 표 "컨텍스트" 칸, 상세 패널 토큰 카드(컨텍스트·출력 합·모델), 에이전트 카드에 Codex 한도 한 줄.
- 설정 `readUsage`(기본 켬). 끄면 Claude 세션 기록을 열지 않고 Codex 는 지금처럼 이벤트 종류만 읽는다.
- **Claude 사용 한도는 하지 않는다**: 문서에 있는 길은 statusLine 입력뿐인데 pitwall 은 사용자의 statusLine 을 건드리지 않는다.

### G7. 무거운 작업이 겹치면 에이전트가 기다리게 하기 (예전 결정 변경, §6, 기본 끔)
- 설정 `heavyGuard`(기본 끔, Claude Code 만). 켜면 Claude 연동이 동기 PreToolUse 훅(Bash·PowerShell 도구만, 제한 3초)을 하나 더 넣는다 —
  settings.json 을 바꾸는 것이므로 연동 켜기와 같은 확인 창·백업을 거친다.
- 훅은 명령을 pitwall 에 보내 답을 받는다. pitwall 이 꺼져 있거나 답이 없으면 아무 일도 없다(종료 코드 0).
- 명령 알아보기: `cd x && vue-tsc` 처럼 이어 쓴 명령은 나눠서 보고, `npm run typecheck`·`pnpm build` 같은 패키지 스크립트는 그 폴더
  `package.json` 의 scripts 에서 **한 단계만** 풀어 본다(에이전트는 보통 스크립트로 실행한다). pitwall 이 읽는 것은 scripts 값뿐이다.
- 훅이 더하는 시간: pitwall 이 켜져 있을 때 300 ms 이하, 꺼져 있을 때 600 ms 이하(연결 제한 0.3초). 실제로 재서 적는다.
- 판단(순수 함수): 그 명령이 무거운 명령 패턴에 맞고, **이미 도는 무거운 작업이 있고, 메모리 단계가 정상이 아닐 때만** 끼어든다.
  같은 세션·같은 패턴은 10분 안에 두 번까지 "지금 실행하지 말고 1분쯤 뒤 다시 실행하세요"로 거절하고(`permissionDecision: "deny"`
  — 이유가 Claude 에게 보인다), 세 번째는 그대로 실행시키며 참고 문구(`additionalContext`)만 붙인다. 스냅샷이 오래됐으면 끼어들지
  않는다. 기록(G3g)에 남긴다.
- RAM 이 넉넉하면 겹쳐도 조용하다는 원칙은 그대로다.

### R. 마무리
- R1 README·설계 문서(무엇을 읽는지·기본 켬/끔·한계), R2 부하 다시 재기(창 닫힘 평균 CPU 1% 미만, 앱 RAM 300 MB 미만),
  R3 전체 검사(타입·린트·테스트·빌드)와 브랜치 전체 검토.

## 3. 비목표
- 에이전트를 끄는 것, 에이전트에게 프롬프트를 보내는 것(G7 은 에이전트가 물어볼 때 답하는 것뿐).
- 무거운 작업을 pitwall 이 끄거나 줄 세우는 것(G7 은 두 번 미루게 하고 놓아준다).
- Claude 사용 한도, 요금($) 계산, 토큰 추이 그래프.
- macOS 의 커밋 값(확인할 Mac 이 없다), 터미널의 특정 탭 고르기.
- 워크트리 자체 지우기(4단계 결정 유지), 서버 다시 띄우기, 여러 PC.
- 다른 포트·다른 앱을 끄는 것(보여 주기만).

## 4. 반목표 (동작하더라도 이러면 실패)
- 확인 없이 끄거나 지우는 것. 사용자의 Claude·Codex 설정을 사용자가 켜지 않았는데 바꾸는 것. `statusLine` 을 건드리는 것.
- 프롬프트·명령·대화 내용을 디스크에 쓰거나 pitwall 밖으로 보내는 것(OS 알림 포함 — 알림에는 도구 이름까지만). `showAgentActivity`·`readUsage` 를 껐는데 읽어 두는 것.
- 오래 쉬는 에이전트의 서버를 **정리 후보·정리 추천**으로 올리는 것("확인해볼 것"까지만).
- 같은 프로세스를 두 번 세는 것(작업 공간 합계 포함).
- pitwall 이 꺼졌거나 느릴 때 에이전트의 도구 실행이 막히거나 늦어지는 것(G7 — 꺼져 있을 때 600 ms, 켜져 있을 때 300 ms 를 넘으면 실패).
- 감시하는 앱이 무거워지는 것(R2). 회사 경로·이름이 레포에 들어가는 것.

## 5. 제약
- Windows + macOS(미검증), 한국어 화면, NeoHtop 부품 모양(새 탭·카드·표는 있는 부품을 쓴다).
- 판단은 순수 함수로 나눠 테스트한다. 버그 수정·규칙 변경은 실패하는 테스트부터.
- 실제 `~/.claude/settings.json`·`~/.codex` 는 테스트에서 건드리지 않는다(임시 폴더).
- 새 의존성을 더하지 않는다.
- Claude 훅 이벤트가 늘어(PreToolUse) 이미 켠 사용자는 "다시 켜 주세요" 상태가 된다. 자동으로 고치지 않는다.

## 7. Claude 가 정한 것(바꿀 수 있음)
- 기준값: 오래 쉬는 세션 180분, 조용함 15분, 다시 알림 10분, 자리 비움 10분, 오래 안 쓴 워크트리 14일, RAM 알림 재무장 5분,
  커밋 단계는 RAM 과 같은 기준 %, 기록 300개·24시간, 프롬프트 200자·명령 160자, G7 은 10분 안에 두 번까지 거절.
- 기본값: `showAgentActivity`·`readUsage`·`notifyClickFocus`·조용함·꺼짐 알림은 켬, `heavyGuard` 는 끔.
- `level` 을 RAM·커밋 중 높은 쪽으로 한 것. 메모리 증가를 커밋으로 재는 것. history.json 을 version 2 로 올려 예전 기록을 버리는 것.
- 남은 프로세스 규칙은 그대로 둔 것. 작업 공간 탭을 기본 탭으로 한 것. 다른 포트·다른 앱은 보여 주기만 하는 것.
- G7 을 Claude Code 만, 거절은 두 번까지로 한 것. Claude 사용 한도를 하지 않는 것.
- (빌더 점검 반영) Claude 세션 파일을 읽어 짝과 상태에 쓰는 것, 짝지은 세션을 만료시키지 않는 것, OS 알림에는 도구 이름까지만 넣는 것,
  G7 이 PowerShell 도구와 패키지 스크립트(한 단계)까지 보는 것과 그 시간 한도(300·600 ms).

## 8. 빌더에게 맡기는 것
- 훅 파일 규격(`HookFileSpec`)을 이벤트마다 다른 항목(비동기 알림·동기 질문, matcher)으로 넓히는 방법과 "켜짐·일부" 판정.
- 스냅샷·IPC 모양의 세부(기록은 스냅샷에 싣지 않고 따로 보내는 쪽을 권한다 — 5초마다 300개를 다시 보내지 않게).
- "창으로 가기"의 조상 고르기 세부, 터미널 여는 명령(Windows Terminal 이 있으면 그것, 없으면 cmd; macOS 는 Terminal).
- 작업 공간 탭의 칸·정렬·접기 기억, 탭이 8개가 되는 도구줄 배치.
- Codex 훅 이벤트에 제목·프롬프트·도구 필드가 오는지 확인하고, 오면 쓰고 없으면 비우는 것.
- 설정 화면에서 새 항목을 어느 구역에 둘지(기준값·알림·에이전트 연동·무거운 작업·디스크 정리 안에서).

## 9. 알려진 위험
- Claude 세션 기록·실행 중 세션 파일은 내부 형식이라 바뀌면 토큰·정확한 짝·훅 없는 상태가 안 보인다(비우고 예전 방식으로 돌아간다).
- 커밋은 예약만 하고 안 쓴 몫도 포함한다 — RAM 값을 바꾸지 않고 나란히 보이는 이유.
- "창으로 가기"는 Windows 의 앞 창 제한 때문에 안 될 수 있다(안 되면 pitwall 을 연다). 개발 중에는 사용자의 화면을 훔치지 않도록
  창 찾기까지만 실제로 확인하고, 앞으로 가져오기는 사용자가 확인한다.
- 조용함 표시는 긴 대기 명령(CI 기다리기 등)에서도 뜬다 — 그래서 "멈춤"이 아니라 "조용함"이라 부른다.
- G7 의 거절을 받은 에이전트가 검사를 건너뛸 수 있다 — 문구에 "다시 실행하세요"를 분명히 하고 두 번 뒤에는 놓아준다.
- 동기 훅은 Bash 실행마다 curl 을 한 번 더 띄운다(켠 사용자만).
