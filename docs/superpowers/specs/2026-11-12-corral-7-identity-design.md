# 7단계: Corral 다운 얼굴 — 새 색과 NeoHtop 과 다른 화면 결

상태: **구현됨**(2026-11-12). 시안은 브레인스토밍 화면(저장소 밖)으로 사용자와 함께 봤고, 그 내용은 이 문서에 모두 옮겼다. 만드는 사람 검토(질문 7개)를 반영했다.

## 1. 왜

화면 디자인을 NeoHtop(MIT)에서 가져와 시작했는데, 지금 보면 색(Catppuccin 의 보랏빛 남색·연보라)과 뼈대(같은 크기 통계 카드 줄 → 테두리 상자 탭 → 프로세스 표)가 NeoHtop 과 너무 닮았다. 라이선스 문제는 아니다(MIT 고지를 지키고 있다). 문제는 Corral 만의 얼굴이 없다는 것이다.

레이아웃을 통째로 바꾸는 안(할 일 먼저 + 작업 공간 보드, 목록 + 상세)도 시안으로 비교했지만, 사용자는 **지금 레이아웃이 더 낫다**고 판단했다. 그래서 큰 틀(카드 줄 → 탭 → 표)은 그대로 두고, 색을 Corral 것으로 바꾸고, NeoHtop 을 떠올리게 하는 세 군데(카드 줄·탭·표)를 Corral 의 목적("지금 손볼 것을 알려 주고 정리하게 해 주기")에 맞게 바꾼다.

## 2. 목표

- **G1 색**: 어두운·밝은 테마 모두 앱 아이콘에서 가져온 **흑회색 + 민트** 팔레트로 바꾼다(창 제목줄·트레이 아이콘·테마 고르기 견본까지).
- **G2 카드 줄**: 할 일이 있는 카드(응답 대기 에이전트·정리 후보 서버)만 눈에 띄게, 0 인 카드는 좁고 조용하게.
- **G3 할 일 띠**: 카드와 탭 사이에, 처리할 일이 있을 때만 나타나는 줄. 한 줄에 하나씩, 버튼 하나로 바로 처리한다.
- **G4 밑줄 탭**: 테두리 상자 탭(세그먼트) 대신 글자 탭 + 민트 밑줄. 다른 앱·기록은 "더 보기"로 묶는다.
- **G5 울타리 표**: 작업 공간 묶음 머리 왼쪽에 상태 색 막대, 구성원 줄은 가지 선으로 잇고, 상태는 색 알약으로. 작업 공간 탭의 구성원 이름은 반복되는 폴더 이름 대신 "무엇인지"(Claude Code·Vite·Playwright 브라우저).
- **G6 픽셀 추이**: 메모리 카드의 추이를 아이콘처럼 계단식 막대로.

## 3. 하지 않는 것

- 레이아웃의 큰 틀 바꾸기(카드 줄 → 탭 → 표 순서, 카드 영역 세 단계, 카드 편집, 상세 패널, 메모리 상세).
- 수집·판단 규칙 바꾸기(언제 응답 대기·정리 후보인지는 그대로. 할 일 띠는 이미 있는 판단을 보여 줄 뿐).
- 트레이 요약 창(`TrayView.vue`)의 배치. 색만 따라 바뀐다.
- 새 글꼴 넣기(Pretendard 그대로).
- 상세 패널·메모리 상세의 그래프 모양(픽셀 추이는 카드에만).

## 4. 하면 안 되는 것(이렇게 되면 실패)

- 바꾼 뒤에도 보랏빛 남색·연보라 같은 Catppuccin 인상이 남는다(한 곳이라도 옛 색이 섞여 보인다).
- 상태 색의 뜻이 흐려진다: 작업 중(초록)·응답 대기(노랑)·정리 후보·오류(빨강)·쉬는 중(회색)이 어두운·밝은 테마 모두에서 한눈에 구분돼야 한다. 밝은 테마의 글자·상태 색은 바탕 대비 4.5:1 이상.
- 할 일 띠가 같은 일을 두 번 보인다(메모리 정리 추천에 든 서버가 정리 후보 줄로 또 나온다).
- 할 일 띠가 갱신 때마다 깜박이거나 줄 순서가 뒤섞여, 누르려던 버튼이 다른 줄로 바뀐다.
- 카드가 0 ↔ 1 을 오갈 때마다 카드 줄 전체가 크게 출렁인다.
- 1280×820 창에서 카드 줄·탭 줄·표가 지금보다 덜 보인다(할 일 띠가 없을 때는 지금과 같은 높이).
- 탭을 키보드로 오갈 수 없게 된다.

- **대비 기준**: 글자는 바탕·카드·옅은 상태 색 바탕(알약) 위 모두 4.5:1 이상, 글자가 아닌 점·막대·띠·테두리는 3:1 이상. 위 값은 이 기준으로 계산해 맞춘 것이다(밝게: 바탕 위 5.1~5.5, 알약 위 4.7~5.1. 어둡게: 알약 위 쉬는 중 5.0, 나머지 5.3 이상. 민트 단추 위 글자 밝게 5.6·어둡게 11.1). 시안의 밝은 테마 색보다 조금 어둡다.
- **카드 아이콘 칩·선 색**(`--chart-*`, 지금 칩·추이 선·`Progress` 기본이 같이 쓴다): 노랑·빨강 계열은 쓰지 않는다(상태 색과 헷갈리지 않게). 개발 서버 `--chart-1` 파랑 `#7fbfe6`(밝게 `#25679e`), 에이전트 `--chart-2` 민트, 메모리 `--chart-3` 보랏빛 회색 `#a7a3c9`(밝게 `#6c62a8`), 디스크 정리 `--chart-4` 국방색 회색 `#b9b39a`(밝게 `#77705a`), 토큰 `--chart-5` 강철 파랑 `#93b4d8`(밝게 `#4f6f94`).
- **메모리 묶음 색**(쌓은 막대·지도·묶음별 추이)은 칩 색과 떼어 전용 토큰으로: 개발 서버 = 정보 파랑, 에이전트 = 민트, 무거운 작업 = 응답 대기 노랑, 다른 앱 = `#a7a3c9`(밝게 `#6c62a8`), 시스템·공유 = `#5e6267`(밝게 `#a5a8a1`). `memory.ts` 의 대응이 이 전용 토큰을 가리키게 한다(지금은 `--chart-1~4`·`--status-idle` 을 빌려 쓴다).
- 지금 쓰는 Catppuccin 이름 토큰(`--lavender`·`--peach`·`--sapphire` 등)은 위 역할에 맞는 새 값으로 채운다. 이름까지 역할 이름(`--status-waiting` 등)으로 바꿀지는 만드는 사람이 정한다. 단 "응답 대기·주의" 색은 한 토큰으로 정하고, 상태 점(`TONE_COLOR.warn`)·카드·할 일 띠·트레이 요약 창·확인 창 경고가 모두 그 토큰을 쓴다.
- **노랑과 빨강의 뜻**: 노랑 = 응답 대기·확인해볼 것·경고(무거운 작업 겹침, 남은 프로세스 있음, 커밋 경고 포함). 빨강 = 정리 후보·오류·위험. 무거운 작업 카드의 겹침 표시는 지금 빨강인데 노랑으로 맞춘다.
- 창 제목줄 색(`src/main/windowChrome.ts` 의 `COLORS`): 어둡게 bar `#17181a`·symbol `#e6e8e3`·background `#111213`, 밝게 bar `#ffffff`·symbol `#1d1f1c`·background `#f6f6f3`.
- 트레이 아이콘(`src/main/tray.ts`): 작업 표시줄·메뉴 막대 위에 놓이므로 테마와 상관없이 어두운 테마 값을 쓴다. 메모리 정상 `#8fdcaa`·경고 `#f0b45c`·위험 `#f07a6e`, 기다리는 에이전트 점 `#f2925a`(경고 노랑과 구분되는 주황).
- 앱 아이콘(`src/main/pixelArt.ts` 의 `APP_LINE`)도 `#8fdcaa` 로 바꾸고 `npm run icon` 으로 다시 만든다(내가 정함: 아이콘과 화면 강조색을 하나로).
- 테마 고르기(`TitleBar.vue` 의 `THEMES` 견본): 밝게 `['#16774a', '#93590a', '#b13a2e']`, 어둡게 `['#8fdcaa', '#f0b45c', '#f07a6e']`. 부제(`text.ts` `bar.themes`): 밝게 "흰 바탕", 어둡게 "흑회색"(지금 "Catppuccin").
- 고지: `app.css` 머리 주석과 `THIRD_PARTY_NOTICES.md` 의 NeoHtop 항목에서 "테마 색 값을 가져왔다"는 부분을 빼고 "색은 Corral 고유"로 고친다(표·카드 규칙 등 남은 것은 그대로 고지).

### G2 카드 줄

- **할 일 강조**: 아래일 때 그 카드 위쪽에 3px 상태 색 띠와 그 색의 옅은 테두리. 카드 높이(자세히 240px·간단히 72px)는 바꾸지 않고 줄도 더하지 않는다.
  - 에이전트 카드: 응답 대기가 하나라도 있으면 노랑. 자세히 단계는 아래 칸에 이미 있는 "응답 대기 n" 숫자를 노랑 굵은 글자로(지금도 노랑이다). 간단히 단계는 설명 한 줄을 `응답 대기 2 · Codex 3분`(가장 오래 기다린 에이전트의 도구·경과)으로 바꿔 노랑으로.
  - 개발 서버 카드: 정리 후보가 있으면 빨강. 자세히 단계는 아래 "정리 판단" 칸의 "정리 후보 n" 숫자를 빨강 굵은 글자로. 간단히 단계는 설명 한 줄을 `정리 후보 1` 로 바꿔 빨강으로.
  - 응답 대기 카드(더할 수 있는 카드): 기다리는 에이전트가 있으면 노랑(지금 칩 색과 같은 조건).
  - 메모리 카드는 지금처럼 경고·위험 단계 색을 쓰고 따로 강조하지 않는다. 무거운 작업·남은 프로세스 카드는 띠 없이 지금처럼 칩·글자 색만(노랑, §5 G1 "노랑과 빨강의 뜻").
- **조용한 카드**: 카드의 큰 값이 0 이고 따로 알릴 것이 없으면 좁게(최소 104px, 늘어나지 않음) 접고 제목과 "없음"만 보인다. 대상: 무거운 작업(0개), 남은 프로세스(보이는 수 0개), 개발 서버(0개), 에이전트(0개), 응답 대기 카드(0명). 메모리·디스크 정리·토큰·최근 기록 카드는 접지 않는다.
  - 자세히·간단히 단계 모두 같은 규칙. 카드 편집 중에는 접지 않는다(편집 단추가 들어갈 자리).
  - 너비 계산은 `layoutState.ts` 의 `cardColumns` 가 조용한 카드 목록을 받아 그 칸을 `minmax(104px, 104px)` 로 만든다.
  - 출렁임: 0 ↔ 1 이 바뀔 때만 칸이 바뀐다. 갱신마다 같은 값이면 그대로.

### G3 할 일 띠

- 자리: 카드 영역 손잡이(TopSplitter) 아래, 탭 줄 위 — 지금 "정리 추천"·"무거운 작업 겹침" 알림 상자가 있는 곳. 이 두 상자는 띠의 줄로 옮기고 없앤다. "자리 비운 사이" 카드는 할 일이 아니라 요약이라 지금 그대로 둔다(띠 위).
- 줄(위에서부터, 같은 종류 안에서는 오래된 것 먼저 — 갱신해도 순서가 바뀌지 않게):
  1. **응답 대기 에이전트**(하나에 한 줄): `Codex · shop-web  권한을 기다려요 · 3분  shell · curl localhost:8080/health  [창으로 가기]`. 이유·하는 일 글자는 지금 표·상세 패널과 같은 문구를 쓰고, "에이전트가 하는 일 보기"가 꺼져 있으면 이유까지만. 창으로 가기를 못 하면 지금처럼 알림 한 줄로 알린다.
  2. **메모리 정리 추천**(메모리가 경고 이상이고 후보가 있을 때 한 줄): 지금 상자의 요약 문구 + 후보 칩(최대 4, 누르면 그 항목 상세) + `[모두 끄기]`.
  3. **정리 후보 서버**(하나에 한 줄, 2 에 든 서버는 빼고): `next :3000 · admin-console  42분 동안 아무도 안 써요 · 620 MB  [내리기]`. 내리기는 지금 서버 끄기와 같은 확인 창을 거친다.
  4. **무거운 작업 겹침**(한 줄): 지금 상자 문구 + `[목록 보기]`.
- 처음에는 3 줄까지 보이고 넘치면 `외 n개` 를 눌러 펼친다.
- 줄마다 오른쪽 끝에 닫기(×). 닫으면 **그 줄의 상태가 바뀔 때까지**(같은 에이전트가 다시 응답 대기가 되거나, 같은 서버의 판단이 바뀌거나, 추천 후보 묶음이 바뀌면 다시 보인다) 숨긴다. 앱을 다시 켜면 다시 보인다(저장하지 않는다). 지금 정리 추천의 `recommendDismissed` 방식과 같다.
- 정리 추천 줄을 닫으면 그 추천에 든 서버도 정리 후보 줄로 따로 나오지 않는다(함께 닫은 것으로 본다). 메모리가 정상으로 내려가 추천 자체가 없어지면, 그때는 아직 정리 후보인 서버가 3 의 줄로 하나씩 나온다(상태가 바뀐 것이라 §4 의 "두 번 보임·갑자기 바뀜"이 아니다).
- 할 일이 없으면 띠는 아예 없다(빈 자리·"할 일 없음" 문구 없음).
- 카드 영역을 "접기" 단계로 두어도 띠는 보인다.
- 줄 왼쪽 점·글자는 G1 상태 색(응답 대기 노랑, 정리 후보 빨강, 메모리 추천은 메모리 단계 색, 겹침은 노랑).

### G4 밑줄 탭

- 메인 화면 탭 줄(`ToolBar.vue`): 테두리 상자 대신 글자 탭. 고른 탭은 굵은 글자 + 민트 밑줄 2px + 민트 숫자. 숫자는 지금처럼(다른 앱·기록은 숫자 없음) 작고 흐리게.
- 탭 순서: 작업 공간 · 개발 서버 · 에이전트 · 남은 프로세스 · 무거운 작업 · 디스크 정리 · **더 보기 ▾**(다른 앱·기록). 더 보기 안의 탭을 고르면 그 자리에 그 이름이 밑줄과 함께 보인다(`기록 ▾`).
- 접근성: `role="tablist"`/`role="tab"`/`aria-selected`, ←·→ 로 탭 이동, 더 보기는 메뉴 단추(`aria-haspopup`).
- 설정 화면 위쪽의 구역 전환(일반·기준값 …)도 같은 밑줄 탭으로 바꾼다(내가 정함: 같은 앱 안에서 탭 모양을 하나로). 목록/묶음, 자세히/간단히/접기 같은 **보기 전환**은 지금처럼 작은 세그먼트로 둔다(탭이 아니라 모드 전환이라서).
- 테스트가 `[data-slot="toggle-group-item"][data-value=…]` 로 탭을 찾는다. 새 탭에도 `data-value` 를 두고, 테스트의 선택자는 새 구조에 맞게 고친다.

### G5 울타리 표

- **묶음 머리**(작업 공간 탭, 개발 서버 탭의 작업 공간 묶음 보기): 왼쪽에 3px 상태 색 막대. 막대 색은 **머리 상태 글자의 색(지금 `GroupHead.status.dot`)을 그대로** 쓴다. 머리 상태를 고르는 규칙(`workspaceStatus`·`groupStatus`)은 바꾸지 않는다. 그래서 막대와 머리 알약은 늘 같은 색이다. 상태 글자가 없는 머리는 회색 막대.
- **가지 선**: 펼친 묶음의 구성원 줄 이름 칸 앞에 묶음에서 이어지는 가는 선(└ 모양, 테두리 색보다 한 단계 밝게).
- **상태 알약**: 모든 표의 상태 칸을 "점 + 글자"에서 "옅은 상태 색 바탕(그 색 12~14%) + 상태 색 글자" 알약으로. **색은 그 칸의 지금 색(`Cell.dot` 의 Tone)을 그대로** 쓴다 — 모양만 바뀌고 어떤 상태가 무슨 색인지는 `rows.ts` 그대로다(running 민트, warn 노랑, stopped 빨강, idle 회색). 점이 없는 상태 칸은 알약 없이 지금처럼 글자만. 알약 안 글자는 지금 문구 그대로("작업 중 · 12분").
- **구성원 이름**(작업 공간 탭만): 이름 칸의 큰 글자를 무엇인지로 — 에이전트는 도구 이름(Claude Code·Codex), 서버는 지금 아이콘을 고르는 브랜드 이름(Vite·Spring Boot …, 모르면 프로세스 이름에서 `.exe` 를 뗀 것), 무거운 작업·남은 프로세스는 지금 이름(vue-tsc·Playwright 브라우저). 워크트리 폴더가 묶음 이름과 다르면(여러 저장소를 묶는 바깥 작업 공간) 이름 뒤에 흐린 글자로 `폴더 · 브랜치`. 풍선말에는 지금처럼 전체 경로. 다른 탭의 이름 칸은 그대로(폴더 이름이 그 탭의 기준이라서).

### G6 픽셀 추이

- 메모리 카드(자세히 단계)의 추이 그래프를 계단식 막대로: 보이는 시간 범위를 같은 너비 칸 24 개로 나눠 칸마다 그 칸 안 값의 최댓값을 막대 높이로. 막대 사이 1px 틈, 모서리 없음. 색은 칸의 값이 넘은 단계 색(정상 민트·경고 노랑·위험 빨강). 기록이 없는 칸은 비운다(지금처럼 끊긴 구간은 잇지 않는다).
- 풍선말·눈금 문구(`10분 · 0~100%`)는 지금 그대로.
- 제목줄의 "실시간" 점을 작은 정사각형으로(내가 정함: 같은 픽셀 결).
- 상세 패널·메모리 상세의 그래프는 바꾸지 않는다.
