# 6단계: 이름(Corral)·화면 배치·메모리를 눈으로

상태: **구현됨**(2026-11-11). 설계 때 만드는 사람 검토(빈 곳 찾기)를 반영했고, 구현하며 바뀐 결정은 §6 끝("구현하며 바뀐 것")에 이유와 함께 적었다(§5 의 해당 줄도 고침).

## 1. 왜

메인 창을 실제로 쓰면서 나온 네 가지 불편에서 시작한다.

1. 위쪽 카드 영역과 아래쪽 표의 크기를 바꿀 수 없다. 표를 오래 보는 날에는 카드가 자리만 차지한다.
2. 위쪽 카드는 늘 같은 여섯 장이다. 사람마다 자주 보는 것이 다르다(예: 응답 대기만 보고 싶다).
3. 메모리가 숫자로만 보인다. 전체 RAM 가운데 개발 서버·에이전트가 몇 %인지, 개발 서버 가운데 어느 서버가 큰지 눈으로 바로 들어오지 않는다.
4. 이름 "pitwall"은 무슨 도구인지 드러나지 않는다. 사용자가 **Corral**(흩어진 에이전트·서버·남은 프로세스를 한 우리에 모은다)로 정했다.

화면 시안: `ui-proposal.html` 과 그 그림 네 장(자세히·간단히·카드 편집·메모리 상세). 시안과 다른 점은 이 문서가 이긴다(특히 표의 막대는 칸 배경, 메모리 지도의 묶음).

## 2. 목표

- **G1 이름**: 사용자와 에이전트가 읽는 곳의 이름을 Corral 로 바꾼다. 기존 설치의 설정·기록·자동 실행·연동 훅은 그대로 이어진다.
- **G2 위아래 크기**: 카드 영역과 표 사이의 손잡이를 끌어 세 단계(자세히·간단히·접기) 가운데 하나에 붙인다.
- **G3 카드 고르기**: 카드를 숨기고, 순서를 바꾸고, 새 카드(응답 대기·토큰과 한도·최근 기록)를 더한다.
- **G4 메모리 구성**: 메모리 카드에 전체 RAM 을 묶음별로 나눈 쌓은 막대와 묶음별 % 를 보인다.
- **G5 표의 메모리 막대**: 표의 메모리 칸 배경에 그 표 안에서의 비중을 막대로 보인다.
- **G6 메모리 지도·묶음 추이**: 메모리 상세(카드의 ↗)에 메모리 지도(트리맵)와 묶음별로 쌓은 추이를 보인다.

## 3. 하지 않는 것

- GitHub 저장소 이름 바꾸기(사용자가 GitHub 에서 할 일. 바꾸면 GitHub 가 예전 주소를 넘겨준다). 업데이트 확인·홈페이지 주소는 그대로.
- 로컬 폴더 이름 바꾸기.
- 카드 크기를 하나하나 바꾸거나 여러 줄로 늘어놓는 자유 배치. 카드는 한 줄에 놓인다.
- 카드 영역의 높이를 아무 값으로나 두는 것. 세 단계에만 붙는다.
- 설치 파일을 이 PC 에서 직접 설치·업그레이드해 보는 것(사용자 확인 목록으로 넘긴다).
- 트레이 요약 창(`TrayView.vue`)의 배치 바꾸기(이름 문구만 바뀐다).

## 4. 하면 안 되는 것(이렇게 되면 실패)

- 업데이트한 사용자의 설정·기록·숨긴 서버·별칭·연동 포트가 사라진다(설정 폴더가 바뀌면 그렇게 된다).
- 이미 켜 둔 Claude·Codex 연동이 "꺼짐"이나 "일부"로 보인다.
- 1280×820 창에서 창 전체에 가로 스크롤이 생긴다.
- 막대·지도가 같은 메모리를 두 번 세거나, 한 줄의 비중이 100% 를 넘는다.
- 새 버전이 쓴 기록 파일을 예전 버전이 읽으면 기록이 모두 사라진다.

## 5. 정한 것

### G1 이름

바꾸는 것(사용자·에이전트가 읽는 곳):
- `src/shared/text.ts` 의 화면 문구 속 제품 이름(앱 이름, 확인 창, 트레이, 알림, 설정 설명 등), 창 제목(`src/renderer/index.html`).
- 질문 훅이 에이전트에게 주는 문구의 머리말 `pitwall:`·`pitwall 참고:` → `Corral:`·`Corral 참고:`.
- `package.json` 의 `productName`(→ `Corral`)과 `name`(→ `corral`, 설치 파일 이름 `corral-<버전>-setup.exe`·`.dmg` 에 쓰임). `electron-builder.yml` 의 `productName`(바로 가기·제거 목록·작업 관리자 설명에 보이는 이름).
- GitHub API 요청의 `User-Agent` → `Corral`.
- README·`docs/measurements.md` 의 제품 이름(지난 단계의 설계·계획 문서는 기록이므로 그대로).

그대로 두는 것(기존 설치가 기대는 내부 이름):
- 앱 ID `io.github.yeonjin1357.pitwall`(NSIS 업그레이드 식별, Windows 알림, 자동 실행 레지스트리 값 이름).
- **실행 파일 이름 `pitwall.exe`**(`executableName`): 바꾸면 업그레이드 설치 프로그램이 실행 중인 예전 앱을 알아보지 못한다.
- **설정 폴더**: Electron 은 `productName` 으로 설정 폴더를 정하므로 이름을 바꾸면 `%APPDATA%\Corral` 로 옮겨 간다. 그래서 메인 진입점이 **다른 어떤 모듈보다 먼저** 읽는 작은 모듈에서 `app.setPath('userData', <appData>/pitwall)` 로 예전 폴더를 고정한다(설정·기록·`localStorage`·연동 포트·토큰이 모두 그 안에 있다). 단 명령줄에 `--user-data-dir` 가 있으면 고정하지 않는다(측정·검증용 별도 프로필).
- 훅 주소 `/pitwall-hook/…`(설치된 훅을 알아보는 표시), IPC 이름(`pitwall:…`, `window.pitwall`), `localStorage` 키(`pitwall.…`), 보조 DLL·백업 파일 이름, C# 도우미 클래스 이름.
- 자동 실행: 지금도 패키지된 앱이 켜질 때 설정대로 다시 등록한다 — 바꿀 것 없음(사용자 확인 목록에만 적는다).

### G2 위아래 크기(세 단계)

- 카드 영역과 도구줄 사이에 가로 손잡이 줄(높이 32px — 구현하며 바뀜, §6)을 둔다. 가운데 잡는 표시, 왼쪽에 단계 버튼 `자세히`·`간단히`·`접기`, 오른쪽에 `카드 편집`.
- 손잡이를 끌면 높이를 따라가다가 놓으면 가장 가까운 단계에 붙는다. 더블클릭 = 자세히 ↔ 접기. 손잡이에 초점이 있으면 ↑·↓ 로 한 단계씩.
- 자세히 = 지금 카드(높이 240px). 간단히 = 카드마다 제목·큰 값·짧은 설명 한 줄(높이 약 72px; 메모리 카드는 % 와 얇은 쌓은 막대). 접기 = 카드 없음(손잡이 줄은 남는다).
- 표 영역은 남는 높이를 모두 쓴다. 지금 반응형 규칙(창 너비·높이에 따른 `app.css` 의 규칙, `.table-section` 높이)은 세 단계와 맞게 고친다.
- 고른 단계는 `localStorage`(`pitwall.topMode`)에 둔다 — `viewState.ts`·`sortState.ts` 와 같은 방식(읽기 실패·모르는 값은 자세히).

### G3 카드 고르기

- 카드 종류: 기본 여섯 장 `memory`·`servers`·`agents`·`heavy`·`leftovers`·`disk` 와 새 카드 세 장 `waiting`·`tokens`·`events`.
- 배치 모양 `{ order: CardId[]; hidden: CardId[] }`: `order` 는 카드 줄에 올라 있는 카드(기본 카드 + 더한 새 카드)의 순서, `hidden` 은 그 가운데 숨긴 것. 새 카드는 `order` 에 있어야 보인다(더하기 = `order` 끝에 넣기, 빼기 = `order` 에서 지우기). 기본 카드는 뺄 수 없고 숨길 수만 있다.
- 읽을 때 정리: 모르는 이름·중복은 버리고, `order` 에 없는 기본 카드는 끝에 붙인다(앞으로 기본 카드가 늘어도 사라지지 않게). 보이는 카드가 하나도 없으면 기본 배치로. 저장은 `localStorage`(`pitwall.cards`), 실패하면 기본 배치.
- 편집 모드(`카드 편집`): 카드마다 `숨기기`/`보이기`(숨긴 카드는 흐리게), 새 카드에는 `빼기`도. 끌어서 순서 바꾸기와 `←`·`→` 버튼(키보드로도). 이 단추들은 카드 아래 가장자리의 작은 막대에 둔다. "더할 수 있는 카드" 칩, `기본값으로`, `완료`는 카드 줄 아래가 아니라 손잡이 줄에 둔다(구현하며 바뀜, §6). 마지막 남은 보이는 카드는 숨길 수 없다. 편집 모드에 들어가면 접기 단계일 때 자세히로 바꾼다.
- 너비: 지금 비율을 지킨다(메모리 카드는 다른 카드의 1.5배). 카드 하나의 최소 너비는 메모리 카드 240px, 나머지 150px(구현하며 바뀜, §6). 한 줄에 다 들어가지 않으면 카드 줄만 가로로 스크롤된다.
- 새 카드 내용:
  - **응답 대기**: 응답 대기인 에이전트 수와 최대 세 줄(폴더 · 이유 · 기다린 시간). 한 줄을 누르면 그 에이전트의 상세 패널. 없으면 "기다리는 에이전트가 없어요".
  - **토큰·한도**: 컨텍스트가 가장 큰 에이전트의 값·폴더와 Codex 한도(5시간·주간). 누르면 에이전트 탭. 둘 다 모르면 "아직 읽은 토큰이 없어요".
  - **최근 기록**: 기록 세 줄(시각·글). 누르면 기록 탭.
- 구조: 지금처럼 `StatsBar.vue` 가 카드 줄을 그리되 `order` 를 따라 그린다. 새 카드 세 장은 작은 컴포넌트로 따로 둔다(StatsBar 가 더 커지지 않게).

### G4 메모리 카드의 구성 막대

- 묶음은 실제 데이터의 다섯 개: 개발 서버·에이전트·무거운 작업·다른 앱(남은 프로세스·다른 포트의 프로세스도 여기에 들어 있다)·시스템·공유. 남은 메모리 = `totalBytes − usedBytes`.
- 지금의 묶음별 작은 막대 네 개 대신: 전체 RAM 한 줄을 묶음 순서대로 나눈 **쌓은 막대**(나머지는 남은 메모리 색) + 그 아래 2×2 범례(개발 서버·에이전트·다른 앱·시스템·공유, 무거운 작업은 0 보다 클 때만 더함)에 묶음 이름과 **전체 RAM 대비 %**. 풍선말에 GB. 10분 RAM 추이 그래프는 그대로.
- 계산은 순수 함수 `memoryComposition(memory, groups)`: 묶음 합이 `usedBytes` 를 넘으면(측정 시점 차이) 묶음들을 같은 비율로 줄여 `usedBytes` 에 맞춘다 — 막대는 100% 를 넘지 않고, 남은 메모리 칸은 늘 정확하다. `totalBytes` 가 0(아직 모름)이면 막대를 그리지 않는다.
- 색은 지금 묶음 색(메모리 상세와 같음).

### G5 표의 메모리 막대

- 표의 메모리 칸 **배경**에 비중만큼 옅은 막대(칸 너비는 그대로). 숫자·정렬은 그대로. 선택된 줄·마우스를 올린 줄·묶음 머리 줄의 배경과 겹쳐도 글자가 읽혀야 한다.
- 비중 = 그 줄의 메모리 ÷ **그 표의 기준**:
  - 기본: 그 표의 맨 위 줄들(묶음 머리 아래 구성원이 아니라 실제 줄)의 메모리 합. **검색으로 거르기 전** 줄로 계산한다(검색해도 막대 길이가 바뀌지 않게). 묶음 머리 줄(개발 서버 탭의 작업 공간 묶음)은 그 묶음 합 ÷ 같은 기준.
  - 작업 공간 탭: 줄끼리 더하면 같은 프로세스를 두 번 셀 수 있으므로 **사용 중인 RAM** 대비.
  - 다른 포트 보기: 한 프로세스가 여러 줄에 나오므로 막대 없음.
  - 메모리 칸이 없는 표(디스크 정리·기록)는 해당 없음.
  - 비중은 0~1 로 자른다.
- 칸의 풍선말: `4.2 GB · 이 표 합의 52% · 전체 RAM 의 7%`(작업 공간 탭은 `사용 중 RAM 의 9%`). 메모리 머리글에도 풍선말로 기준을 적는다(머리글 풍선말 칸을 새로 만든다).
- 구현 모양: 표 정의(`Cell`)에 비중 값을 더하고, 표마다 기준을 정해 비중을 채우는 순수 함수를 둔다(검색 전 표에 적용). 표 그리기(`ItemTable.vue`)는 그 값으로 배경 막대를 그린다.

### G6 메모리 지도·묶음 추이(메모리 상세)

- **메모리 지도**: 사각형 넓이 = 메모리. 1단계는 G4 의 다섯 묶음(0 인 것은 뺀다). 2단계는 그 묶음의 줄: 개발 서버 = 서버 줄(`이름 · 작업 공간`), 에이전트 = 에이전트 줄, 무거운 작업 = 작업 줄, 다른 앱 = 앱(큰 순 12개 + "기타 n개"), 시스템·공유 = 한 칸.
  - 에이전트 칸은 표의 메모리가 아니라 무거운 작업을 뺀 자기 몫(`ownMemoryBytes`)이다(구현하며 바뀜, §6). 그래도 2단계 합이 묶음보다 크면(측정 시점 차이 등) 같은 비율로 줄여 묶음 칸에 맞추고, 작으면 남는 자리를 "그 밖" 칸으로 채운다 — 지도는 늘 묶음 값과 맞다.
  - 사각형을 누르면 메모리 상세를 닫고 그 줄의 상세 패널을 연다(지금 `select` 와 같은 길). 줄이 없거나 찾을 수 없는 칸(앱·숨긴 서버·그 밖·시스템)은 누를 수 없다.
  - 작은 사각형은 글자를 숨기고 풍선말로. 배치는 정사각형에 가까운 트리맵(squarify) 순수 함수.
  - 남은 메모리는 지도에 넣지 않고 제목 아래 글로.
- **묶음별 추이**: 지금의 RAM 추이 그래프 **아래에** 묶음별 메모리를 쌓은 그래프(같은 시간 창). 새 컴포넌트.
  - 기록: 메인이 30초마다 RAM % 를 남기는 바로 그 자리에서 묶음별 바이트(`{ t, devServer, agent, heavy, otherApps, system }`)도 함께 남긴다. 값은 메모리 카드·지도와 같이 사용량에 맞춰 줄인 값이다(구현하며 바뀜, §6). `history.json` 은 **판을 올리지 않고**(`version: 2` 그대로) 선택 칸 `groups` 를 더한다 — 예전 버전은 모르는 칸을 버리고 읽고, 새 버전은 칸이 없으면 빈 기록으로 시작한다(새 버전이 쓴 파일을 예전 버전이 읽어도 기록이 사라지지 않게). 보관 시간은 RAM 기록과 같다(2시간).
  - 전달: 새 IPC `historyGroups()`(이름은 `pitwall:history-groups`) — 지금 `historyRam()` 의 모양은 바꾸지 않는다.
  - 렌더러: RAM 기록과 같은 규칙으로 스냅샷마다 묶음 점을 더하고, 메인 기록으로 처음 채우고, 같은 방식으로 솎는다.

## 6. 이번에 정한 것(내 결정 — 사용자가 확인할 것)

- 이름 바꾸기는 보이는 이름만. 실행 파일 이름(`pitwall.exe`)·앱 ID·설정 폴더·훅 주소·IPC·`localStorage` 키·GitHub 주소는 그대로 — 기존 설치가 끊기지 않게.
  - 그 뒤 사용자가 GitHub 저장소 이름을 `Corral` 로 바꿔(2026-11-11), 업데이트 확인·릴리스 페이지 검사·홈페이지·설정 화면 링크·README·릴리스를 올릴 저장소(`publish.repo`)를 새 이름으로 바꿨다. 예전 주소는 GitHub 가 새 주소로 넘겨주므로 이미 설치된 버전도 계속 업데이트를 확인한다(단 macOS 의 예전 버전은 릴리스 주소 검사가 예전 이름이라 새 버전 알림이 뜨지 않는다 — 한 번 직접 내려받아야 한다).
- 카드 영역은 자유 높이가 아니라 세 단계에 붙는다 — 카드가 중간에 잘리지 않게.
- 표의 메모리 막대는 칸 배경에 깔고 % 는 풍선말로 — 1280 창에 들어가야 해서.
- 표 막대의 기준은 그 표 줄들의 합(작업 공간 탭만 사용 중 RAM, 다른 포트 보기는 없음) — "개발 서버 안에서 누가 큰지"가 질문이었고, 묶음 합을 기준으로 하면 100% 를 넘는 탭이 있다.
- 메모리 지도의 묶음은 실제 데이터의 다섯 묶음(남은 프로세스는 다른 앱 안) — 따로 그리면 두 번 센다.
- 화면 배치(단계·카드 배치)는 설정 파일이 아니라 `localStorage` — 지금 보기·정렬 기억과 같은 방식.
- 묶음 추이는 메인 기록에 남기되 기록 파일 판은 올리지 않는다.

### 구현하며 바뀐 것(2026-11-11)

- 실행 파일 이름은 끝까지 `pitwall`(`executableName`) — 바꾸면 업그레이드 설치 프로그램이 실행 중인 예전 앱을 알아보지 못한다(작업 관리자 "세부 정보"에 `pitwall.exe` 로 보이는 것은 받아들임).
- 카드 최소 너비 200px(모두) → 메모리 카드 240px·나머지 150px — 200px 이면 1280px 창에서 메모리 카드가 216px 로 좁아져 범례가 잘렸다. 예전 배치는 1180~1280px 창에서 다른 카드가 161~176px 였다. 나머지를 160px 로 두면 1280px 창의 카드 줄(1176px)에 일곱 장(1200px)이 들어가지 않아 150px(1140px).
- 메모리 지도의 에이전트 칸은 무거운 작업을 뺀 자기 몫(`AgentRow.ownMemoryBytes`, 메인이 에이전트 묶음과 같은 규칙으로 센다) — 표의 메모리(자손의 무거운 작업까지)로 묶음을 나누면 무거운 작업을 띄운 에이전트의 칸이 부풀었다. 표와 값이 다른 칸은 풍선말에 "무거운 작업 제외". 에이전트 표는 그대로 무거운 작업까지 센다.
- 편집 막대(더할 수 있는 카드·기본값으로·완료)는 카드 줄 아래가 아니라 손잡이 줄 안(편집 중에는 단계 버튼 자리) — 편집 중에도 카드 영역 높이가 단계 높이 그대로라 끌기·붙기 계산이 어긋나지 않는다. 카드마다의 단추는 카드 아래 가장자리에 둬 제목·큰 값을 가리지 않는다.
- 카드가 넘쳐 카드 줄에 가로 스크롤바가 생기면 그 높이를 재어 끄는 높이·붙는 높이에 더한다(스크롤바는 6px 로 얇게) — 숨기면 스크롤할 수 있다는 것을 모르고, 그냥 두면 카드 아래가 잘린다.
- 손잡이 줄 높이 약 14px → 32px — 단계 버튼·카드 편집 버튼·편집 막대가 들어가야 한다.
- 편집 중에 접으면(더블클릭·끌기) 편집도 끝낸다 — 편집할 카드가 보이지 않는다.
- 메모리 상세 너비 448px → 672px(`max-w-2xl`) — 메모리 지도의 칸 글자를 읽을 수 있게.
- 묶음 값은 기록할 때 사용량에 맞춰 줄인다(메모리 카드·지도와 같은 함수) — 묶음별 추이의 맨 위가 같은 때의 지도·RAM 사용량과 맞는다.
- 묶음 기록 전달은 새 IPC `historyGroups()`(`pitwall:history-groups`), `historyRam()` 은 그대로 — 예전 모양에 기대는 곳(RAM 추이 첫 채우기)을 바꾸지 않는다.

## 7. 만드는 사람에게 맡기는 것

- 카드별 "간단히" 모양의 세부, 손잡이·편집 모드의 세부 모양(시안과 같은 느낌).
- 트리맵 글자 크기·숨기는 기준, 묶음 추이 그래프의 세부 모양.
- 막대 색의 옅기(선택·묶음 머리 배경 위에서도 글자가 읽히게).

## 8. 확인

- 순수 함수는 테스트로: `memoryComposition`, 표 비중 채우기, 카드 배치 정리·조작, 단계 저장, 트리맵 배치·지도 칸 만들기, 기록 `groups` 읽기·쓰기(예전 파일·새 파일).
- 화면은 1280×820 에서 직접 그려 본다(가짜 IPC 로 렌더러만 — 메인을 이 PC 의 설정 폴더로 띄우지 않는다): 세 단계, 편집 모드, 메모리 카드, 표 막대(선택·묶음 머리 줄 포함), 메모리 상세. 창 전체 가로 스크롤이 없어야 한다.
- 사용자 확인 목록: 새 이름으로 빌드한 설치 파일로 예전 버전을 업그레이드했을 때 설정·기록·자동 실행·연동이 그대로인지, 시작 메뉴·작업 관리자·알림에 보이는 이름, 예전 설치 폴더가 남지 않는지.
